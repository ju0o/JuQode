# Phase 4A — Functional Prototype

> **Status:** 동작하는 프로토타입. 완제품이 아니다.
> **설계 SSOT:** [`../design/MVP_DESIGN_CONVERGENCE.md`](../design/MVP_DESIGN_CONVERGENCE.md) ·
> [`../design/mvp-design-convergence.html`](../design/mvp-design-convergence.html)
> **근거:** `evidence/phase-4a/` — **실제 프로토타입을 눌러서 얻은 화면**이다. 설계 HTML이 아니다.
> **Lovable credits 사용:** **0**

## 1. 여는 방법

```
prototype/index.html 을 브라우저로 열면 끝이다.
```

`npm install` · 빌드 · localhost 서버 · 인터넷 · 로그인 **전부 필요 없다.**
`index.html` 하나로 완결되어 있고 **외부 요청이 0건**이다(웹폰트도 불러오지 않는다).

소스를 고쳤을 때만:

```bash
node prototype/build.mjs      # src/ → 자기완결 index.html
```

| | |
|---|---|
| `prototype/src/world.js` | **동결된 물리 엔진.** 설계 HTML에서 그대로 옮겼다. 표상을 다시 만들지 않았다 |
| `prototype/src/data.js`  | 시연 Software 하나 — 자리 · 문제 · 맥락 · 해부도 · 결과 (전부 목) |
| `prototype/src/app.css`  | 껍데기. 토큰·기하·리듬은 수렴 문서에서 왔다. 새 토큰 없음 |
| `prototype/src/app.js`   | **상태 기계 · 물리 애니메이션 · 상호작용** |

## 2. Lovable 을 쓰지 않은 이유

예산은 5–8 credits였고 **0을 썼다.** 판단 근거:

1. **Software World가 손으로 조율한 캔버스 물리 엔진**이다(등치선 + 방향장 스트림라인, 스프링 감쇠기).
   Lovable은 React + Tailwind + shadcn 을 쓴다. 이 엔진을 보지 못한 상태에서 다시 구현하면
   표상이 달라진다 — 그것은 Builder가 아니라 Designer의 일이고, 금지된 일이다.
2. 지시서가 금지한 것이 정확히 **generic shadcn dashboard · rounded card wall · sidebar-first**인데,
   그것이 Lovable의 기본 산출물이다.
3. 저장소에 **이미 적절한 프론트엔드 스택**이 있었다(Phase 3의 자기완결 vanilla + `build.mjs`).
   지시서: *"If the existing project already has an appropriate frontend stack, work with it."*
4. 지시서: *"If something can be fixed directly in code, fix it directly."*

결과적으로 **동결 설계와 픽셀 단위로 같은** 껍데기를 얻었고, 예산은 다음 단계에 남아 있다.

## 3. 하나의 기계, 아홉 개의 상태

여덟 개의 설계 프레임을 **여덟 개의 페이지로 만들지 않았다.** 껍데기는 한 번도 바뀌지 않는다 —
`상단 한 줄 38 · World · 도구 판 하나 · 말하는 한 줄 54`. 그 안의 상태만 바뀐다.

```
launcher
  └ openSoftware()
       ↓
    idle ──pick/World 클릭──► focused ──타이핑──► prepared ──⏎──► working
      ▲                          │                                  │
      │                          └──깊이──► (lens=deep)              ↓
      │                                                          settled
      │◄────────────────── 이전으로 돌아가기 ◄──────────────────────┘
      │
      └──실행──► running ──관측──► focused (새 문제가 1번)
```

`prototype/src/app.js` 의 `S` 객체 하나가 전부다. 흩어진 boolean 더미를 만들지 않았다.
화면은 `render()`, 몸은 `syncWorld()` — 둘 다 `S`의 순수한 함수다.

### 목이 아닌 것

| | |
|---|---|
| 문제 선택 | 지표 행 클릭 **또는 World의 자리 직접 클릭**. 둘 다 같은 자리를 집는다 |
| 집힘 | 스프링 감쇠기가 `coh` · `lab` · 전역 감광을 실제로 보간한다. 잘라 붙이지 않는다 |
| 말하는 줄 | 진짜 `<input>`. 주어는 제품이 쓰고 사용자는 술어만 친다 |
| Qode 시작 | `⏎` 가 실제로 상태를 전이시킨다 |
| 교란 | `m.breath` 로 **그 자리만** 실제로 진동한다(엔진 기능) |
| 결과 | 문제 배열에서 실제로 빠지고, 이음매가 애니메이션으로 풀리고, 번호가 다시 매겨진다 |
| 실행 | 2.4초 관측 뒤 **새 문제를 실제로 몸에 넣는다.** 결이 끊기는 애니메이션이 보인다 |
| 되돌리기 | 이전 평형 스냅샷을 **실제로 복원한다.** 장식용 죽은 버튼이 아니다 |
| 깊이 | 집힌 자리의 해부도를 실제로 바꿔 보여준다 |
| 호버 | `JQ.meaningAt()` 로 가리킨 좌표의 지배적 의미를 계산해 이름을 띄운다 |

### 목인 것

Software 실행 · 코딩 에이전트 · 파일 목록 · API · 스키마 · 결과 수치 · 소요 시간.
**밑에서 돌아가는 것을 목으로 했고, 사용자의 상호작용은 목으로 하지 않았다.**

## 4. 눌러 보고 고친 것 (Visual QA)

실제로 브라우저를 띄워 전 구간을 클릭·타이핑해서 통과시켰다. 소스만 읽어서는 나오지 않은 결함들:

| 발견 | 고침 |
|---|---|
| **말하는 줄에 사각형 테두리가 생겼다.** `:focus-visible` 이 입력줄에 상자를 그렸다 — 정확히 금지된 "chat UI 회귀" | 이 줄만 초점 테두리를 없앴다. 초점은 **커서**가 말한다 |
| **버튼을 누른 뒤 `⏎` 가 Qode를 시작하지 않고 방금 누른 버튼을 다시 눌렀다** | 무엇을 누르든 커서가 말하는 줄로 돌아온다(`refocus()`). 치는 것이 주 행위이므로 |
| **`⌘R` 이 리눅스에서 두부(□)로 나왔다** | 플랫폼을 보고 `CTRL R` / `⌘R` 을 고른다 |
| 런처 콘솔 오류 — 모델이 없는데 애니메이션 루프가 돌았다 | `req()` · `tick()` 에 가드. 콘솔 오류 **0건** |
| World가 큰 창에서 성기게 읽혔다 | 결 굵기를 화면 픽셀 기준으로 고정(`lwK = 0.95/s`)하고 배율 상한을 **1.70**으로 — 설계 보드의 몸 비율(폭 74%)과 같아진다 |

### 회귀 점검 — 전부 통과

| | |
|---|---|
| 클리핑 | 1920×1080 · 1440×900 · 1280×720 · 1100×680 · 900×620 **전부 몸이 잘리지 않는다**(사방 여백 양수) |
| 판 쌓임 | 모든 상태·모든 크기에서 `.band` 개수 **정확히 1** |
| 페이지 스크롤 | 세로·가로 **0** |
| 죽은 컨트롤 | 없음. 4A에서 안 열리는 것(`시간` · `연결` · 런처의 다른 Software · `새로 가져오기`)은 `aria-disabled` + `ink4` + 이유를 담은 `title` 로 **보이게 비활성** |
| 문제 수 | 상단·판·World 번호가 모든 전이에서 일치 |
| 번호 사상 | World의 `1 · 2` = 지표의 `1 · 2`. 문제가 빠지면 즉시 다시 매겨진다 |
| 집힘 ≠ 실패 | 집힘은 **빛**(감광 + 부드러운 빛무리), 실패는 **색과 결의 거동**. 겹치지 않는다 |
| 키보드 | `⏎` Qode · `Ctrl/⌘ R` 실행 토글(**페이지를 새로 고치지 않는다**) · `Esc` 깊이 닫기 → 집힘 풀기 |
| 콘솔 | 오류 **0건** |

## 6. 프로토타입에만 있는 한계

1. **Software 하나만 열린다.** 런처의 `사내 대시보드` · `문서 파이프라인` 은 몸과 상태만 보여주고 열리지 않는다(비활성 표시).
2. **`시간` · `연결` 렌즈는 열리지 않는다.** 4A 범위 밖이므로 만들지 않았다. 비활성으로 표시했다.
3. **`새로 가져오기` 세 갈래도 동작하지 않는다.** 저장소 파싱은 4A 범위 밖이다.
4. **고칠 수 있는 문제는 세 가지로 미리 정해져 있다**(`결제 요청` · `사용자 저장` · `세션 유지`).
   문제가 없는 자리(`로그인` · `요청 받기`)를 집고 말하면 말하는 줄이
   `이 자리엔 고칠 문제가 없어요` 라고 알린다 — 가짜로 성공시키지 않는다.
5. **Software 전체를 대상으로 한 Qode는 없다.** 자리를 집지 않고 말하면
   `문제 번호를 누르세요` 라고 알린다. 제품에서는 정당한 행위지만 4A에서는 목이 없다.
6. **실행 관측은 한 번만 새 문제를 찾는다.** 두 번째 실행부터는
   `이미 아는 문제만 다시 보였어요` 또는 `새로 발견한 문제가 없어요` 로 정직하게 답한다.
7. **되돌리기는 한 단계**다. 직전 평형 하나만 기억한다.
8. **상태는 새로 고치면 사라진다.** 저장소도 서버도 붙이지 않았다.
9. **자리 이름 훑어보기는 호버뿐이다.** 터치 기기에는 통로가 없다 — 설계의 미해결 질문이 그대로 남아 있다.
10. **데스크톱 전용.** 900×620까지 안전하지만 모바일·태블릿 레이아웃은 설계하지 않았다.

## 7. 건드리지 않은 것

동결 설계 산출물(`docs/design/MVP_WIREFRAME.*` · `docs/design/MVP_DESIGN_CONVERGENCE.*` ·
`docs/design/evidence/**`)은 **한 글자도 고치지 않았다.** 구현을 쉽게 하려고 설계를 바꾸지 않았다.

제품 방향도 그대로다 — World가 주 인터페이스 · `SEE → POINT → SAY` · `RUN = 관측` ·
맥락 자동 준비 · 결과 Outcome-first · 기술적 사실은 깊이에만 · 상시 IDE 껍데기 없음 · Realm 하나.
