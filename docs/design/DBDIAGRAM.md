# dbdiagram.io 제출

제출은 **링크 하나**입니다. 그래서 전체를 **다이어그램 한 장**에 올립니다.

## 올리는 법

1. https://dbdiagram.io → **New Diagram**
2. 왼쪽 편집기 내용을 **전부 지우고**, `docs/design/erd.dbml` 을 **통째로 붙여넣기**
3. 오른쪽에 그림이 뜨는지 확인
4. 이름을 `JuQode ERD` 로 저장
5. 우상단 **Share** → 링크 복사 → 제출

전체 49표 · 관계 49개 · 그룹 11개입니다.

## 그림에서 무엇을 보게 되는가

| 그룹 | 뜻 |
|---|---|
| **읽는 법** | 표기 규칙 범례. 데이터가 아니라 안내다 — 각 줄의 말풍선에 뜻이 있다 |
| **MVP ·** 5개 그룹 | **지금 실제로 도는 것.** 로컬 SQLite 26표 |
| **V1 ·** 4개 그룹 | **배포부터 생기는 것.** 서버 Postgres 21표 |
| **제안 ·** | **아직 없는 것.** 마이그레이션이 필요하다 |

## 표기 규칙

| 표기 | 뜻 |
|---|---|
| (표시 없음) | **지금 있다** — `schema.sql` + 마이그레이션에 실재 |
| `note: '제안'` | **아직 없다** — 마이그레이션 필요, 아직 쓰지 않음 |
| `note: 'V1'` | **V1부터 생긴다** — 지금 스키마에는 없다 |
| `note: 'MVP/미사용'` | 컬럼은 있으나 아무도 값을 넣지 않는다 |
| 표 아래 `Note` | DBML 로 표현할 수 없는 것만 — CHECK · 부분 인덱스 · 시드 · 신뢰 경계 · 알려진 구멍 |

같은 내용이 `_READ_ME` 표로 다이어그램 안에도 있습니다. 코드 패널을 보지 못하는 사람도
읽을 수 있게 하기 위해서입니다.

## 그리지 않은 연결 셋 — 일부러입니다

| 연결 | 왜 |
|---|---|
| `project.owner_id → profile.id` | **데이터베이스가 달라** 외래키로 강제되지 않는다. 선을 그으면 강제된다고 읽힌다 |
| `work.outcome → work_outcome.code` | 컬럼이 nullable(`status='ended'` 일 때만 채워진다). dbdiagram 의 다대일은 자식이 NOT NULL 이어야 한다 |
| `change_group.confidence → confidence.code` | 같은 이유 (설명 전에는 null) |

셋 다 `_READ_ME` 와 해당 표의 `Note` 가 적고 있습니다. NOT NULL 로 적으면 **거짓이 되므로**
적지 않았습니다.

## 고칠 때

`erd.dbml` 을 고치고 **올리기 전에** 검사기를 돌리세요.

```sh
node docs/design/check-dbml.mjs
```

### 검사기가 잡는 것 — 전부 실제로 거절당했던 것들입니다

- **Note 안의 홑따옴표** — dbdiagram 은 `''` 를 이스케이프로 읽지 않고 문자열이 끝났다고
  본다 (`A Note can only contain one quoted string`). 값을 감싸야 하면 `「」` 를 쓸 것
- **복합 PK 를 컬럼마다 `[pk]`** — 각 컬럼이 단독 unique 로 읽혀 관계 연산자가 거절된다.
  `indexes { (a, b) [pk] }` 로 적을 것
- **nullable 컬럼에 `>`** — 다대일은 자식 쪽이 NOT NULL 이어야 한다
- **단독 unique 컬럼에 `>`** — 그건 1:1 이므로 `-` 를 쓸 것
- 없는 표를 가리키는 관계, 어느 TableGroup 에도 안 든 표

## 원본이 어디인가

`app/main/db/schema.sql` 과 `app/main/db/db.js` 입니다. **이 그림은 사본입니다.**
값이 다르면 원본이 맞고, 그림을 고쳐야 합니다.
