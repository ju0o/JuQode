# dbdiagram.io 에 올리는 법

dbdiagram 은 **다이어그램 하나에 파일 하나**입니다. 그리고 이 ERD 는 사실 데이터베이스가
둘이라, 한 장에 그리면 보는 사람이 *지금 있는 것*과 *앞으로 생길 것*을 구분할 수 없습니다.

## 세 개로 나눠서 올리세요

| 순서 | 파일 | 무엇 | 표 |
|---|---|---|---|
| 1 | `erd-1-mvp-local.dbml` | **지금 실제로 있는 것** — 로컬 SQLite | 26 |
| 2 | `erd-2-v1-server.dbml` | **배포(V1)부터 생기는 것** — 서버 Postgres | 21 |
| 3 | `erd-3-proposed.dbml` | **아직 없는 것** — 마이그레이션이 필요한 제안 | 1 |

전체를 한 장에 보고 싶으면 `erd.dbml` (48표). **제출용으로는 권하지 않습니다** — 크고,
단계가 섞여 보입니다.

## 올리는 순서

1. dbdiagram.io → **New Diagram**
2. 왼쪽 편집기의 내용을 **전부 지우고** 파일 내용을 **그대로 붙여넣기**
3. 오른쪽에 그림이 뜨면 저장하고 이름을 파일명대로 붙이기
4. 1~3 을 세 번 반복

## 외부 디자이너에게 줄 때

dbdiagram 우상단 **Share** → 링크를 보내면 됩니다. 편집까지 하게 하려면 팀 기능이 필요하고,
보기만 하면 되면 링크로 충분합니다. `Export` 로 PNG · PDF · SQL 로 뽑을 수도 있습니다.

## 읽는 법 — 표기 규칙

| 표기 | 뜻 |
|---|---|
| (표시 없음) | **지금 있다.** `schema.sql` + 마이그레이션에 실재 |
| `note: '제안'` | **아직 없다.** 마이그레이션이 필요하고 아직 쓰지 않았다 |
| `note: 'V1'` | **V1 부터 생긴다.** MVP 스키마에는 없다 |
| `note: 'MVP/미사용'` | 컬럼은 있으나 지금 아무도 값을 넣지 않는다 |
| 표 아래 `Note` | DBML 문법으로 표현할 수 없는 것만 — CHECK 제약 · 부분 인덱스 · 시드 · 신뢰 경계 · 알려진 구멍 |

## 왜 두 그림이 선으로 이어지지 않나

로컬 `project.owner_id` 가 서버 `profile.id` 를 가리키지만 **데이터베이스가 달라 외래키로
강제되지 않습니다.** 선을 그으면 강제된다고 읽히므로 긋지 않았고, `project` 의 Note 가 그
사실을 적습니다.

그리고 **서버는 클라이언트가 보낸 사용자 ID 를 읽지 않습니다** — 로그인 토큰에서 서버가
직접 꺼낸 값만 씁니다. 그래서 이 논리적 연결은 화면에 그리는 것이지 신뢰하는 것이 아닙니다.

## 고칠 때

`erd.dbml` **하나만** 고치고 아래를 돌리세요. 조각 셋은 거기서 나옵니다.

```sh
node docs/design/check-dbml.mjs    # dbdiagram 이 거절하는 모양이 있는지
node docs/design/split-dbml.mjs    # 조각 셋을 다시 만든다
```

조각을 직접 고치지 마세요 — 다음 분할 때 덮어써집니다.

### 검사기가 잡는 것

실제로 dbdiagram 에서 거절당했던 것들입니다.

- **복합 PK 를 컬럼마다 `[pk]`** → 각 컬럼이 단독 unique 로 읽혀 관계 연산자가 거절된다.
  `indexes { (a, b) [pk] }` 로 적을 것
- **nullable 컬럼에 `>`** → 다대일은 자식 쪽이 NOT NULL 이어야 한다
- **Note 안의 홑따옴표** → dbdiagram 은 `''` 를 이스케이프로 읽지 않고 문자열이 끝났다고
  본다 (`A Note can only contain one quoted string`). 값을 감싸야 하면 `「」` 를 쓸 것
- 관계가 이 그림에 없는 표를 가리키는 것
- 어느 TableGroup 에도 안 들어간 표
