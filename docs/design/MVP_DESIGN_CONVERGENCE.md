## 1. 먼저 — 렌더된 판을 보고 한 비판

`evidence/mvp-wireframe/` 의 여덟 장을 실제로 열어서 봤다. 설명 문구가 아니라 픽셀을 봤다.

### 1.1 시각적으로 약한 것

| 무엇 | 왜 약한가 |
|---|---|
| **말하는 줄** | 제품에서 가장 중요한 행위(SAY)가 화면에서 **가장 가벼운 요소**였다. 13.5px 회색 안내문 + 오른쪽 끝 `⏎`. 테두리만 없는 ChatGPT 입력줄이다 |
| **집힘(focus)** | 문제 상태와 집힌 상태가 **거의 같은 모습**이었다(둘 다 붉은 테두리 + 라벨). 02와 03을 나란히 놓아도 구분되지 않는다 |
| **상단 다섯 단어** | `시간 실행 가져오기 연결 깊이` 가 전부 같은 크기·같은 색·같은 자간. **동사(실행)와 렌즈(깊이)가 같은 문법**을 쓰고 있었다. 임의로 고른 다섯 단어처럼 보인다 |
| **타입 스케일** | 13.5 · 12.5 · 11.5 · 9 · 8.5 … 열네 가지 크기가 근거 없이 섞여 있었다. 이것이 “와이어프레임처럼 보인다”의 실제 원인이다 |
| **왼쪽 기준선** | 껍데기는 14px, 런처는 26/30px. 화면마다 글이 다른 자리에서 시작한다 |

### 1.2 일반적(generic)인 것

- **문제 모듈** — 항목 사이에 세로 괘선을 넣은 두 칸 배치. SaaS 대시보드의 **지표 스트립(stat strip)** 문법이다.
- **런처** — 3열 썸네일 카드 갤러리. Notion 템플릿 첫 화면과 구별되지 않는다. 축소판은 **낙서처럼 희미**했다(축소하면서 선 굵기가 같이 줄었기 때문).
- **맥락 줄** — `준비됨 · 결제 요청 · 외부 결제 호출 · …` 은 그냥 **칩(chip) 행**이다.
- **결과 판** — 먹선 테두리 + 볼드 헤드라인 + 링크 셋. 성공 **토스트**로 읽힌다. `확인됨` 은 오른쪽 위에 떠 있는 **배지**였다.
- **07의 붉은 `NEW`** — 색을 상태에만 쓴다는 자기 법칙을 스스로 깼다.

### 1.3 마무리가 안 된 것

- **06과 08에서 World가 잘렸다.** 판이 늘어나면 World를 밀어내는 구조여서 몸의 아래쪽이 실제로 절단됐다. 이건 스타일 문제가 아니라 **결함**이다.
- **판이 1개에서 4개까지 쌓였다.** 02는 띠 1개, 04는 3개, 06은 3개. 여덟 장이 한 기계의 여덟 상태가 아니라 **여덟 개의 별개 목업**으로 읽힌다.
- **08은 몸을 왼쪽으로 밀어 반쪽만 남겼다.** “깊이 들어간다”가 아니라 **깨진 화면**으로 보인다.
- `past #5B6B84` 는 정의만 되고 **한 번도 쓰이지 않았다.**
- 런처 목록의 빈 `<i>` 두 개가 오른쪽 끝을 들쭉날쭉하게 만들었다.

### 1.4 눈이 먼저 가는 곳 — 맞는가

**아니다.** 02에서 눈은 **왼쪽 아래의 큰 붉은 덩이**(사용자 저장)로 먼저 간다. 그런데 아래 모듈의 **첫 항목은 결제 요청**(오른쪽 위)이다. World의 읽히는 순서와 목록의 순서가 어긋나 있었다. 07은 더 심하다 — 방금 생긴 문제(오른쪽)보다 **낡은 문제(왼쪽 아래)가 더 크고 진하다.**

### 1.5 나머지 질문에 대한 답

- **문제 모듈이 우아한가** — 아니다. 얇긴 했지만 **World와 이어져 있지 않았다.** 누르기 전에는 어느 줄이 어느 자리인지 알 수 없다.
- **아래 입력이 채팅 같은가** — 그렇다. 가장 큰 결함.
- **상단이 의도적인가** — 아니다. 임의적이다.
- **깊이가 IDE 냄새가 나는가** — **난다.** 오른쪽 352px 세로 레일 + `파일 · 코드 · API · 스키마 · 증거` 탭줄. 한국어 라벨을 붙인 VS Code 사이드바다.
- **런처가 JuQode 같은가** — 아니다. 어떤 파일 선택기라도 될 수 있다.
- **여덟 장이 하나의 제품인가** — 아니다.

### 1.6 KEEP · MODIFY · KILL

**KEEP** — 결/Field 표상과 물리 엔진 · 색은 상태에만 · 문제는 사람 말 두 줄 · `문제 모듈 → Focus → Qode` 순서 · 맥락은 접힌 한 줄 · 결과는 Outcome-first · 07의 순환 · 문제 0이면 모듈도 없다 · 파일은 깊이에만.

**MODIFY** — 상단 한 줄(세 구역으로) · 말하는 줄(주어를 미리 쓴 문장으로) · 문제 모듈(번호 붙은 지표로) · 집힘(빛으로) · 결과(문장과 계측으로) · 런처(행 목록으로) · 판 구조(언제나 하나) · 타입 스케일(여덟 단계로) · 왼쪽 기준선(22px 하나로).

**KILL** — 상단의 `가져오기` · 깊이의 오른쪽 세로 레일 · 깊이의 탭줄 · 붉은 `NEW` 배지 · 결과의 떠 있는 `확인됨` 배지와 상자 · 문제 모듈의 세로 괘선 · 런처의 카드 갤러리와 3행 리스트 · 05의 “기다리는 동안…” 안내문(입력줄을 죽이는 문구) · `어떻게 확인했나요?`(계측이 이미 답한다) · 판이 두 겹 이상 쌓이는 구조.

## 2. 결정 — 하나의 방향

### 2.1 껍데기 — 판은 언제나 하나다

```
┌ 상단 한 줄 · 38px ──────────────────────────────────────┐
│  정체 · 상태          [ 실행 ]           시간 · 연결 · 깊이 │
├─────────────────────────────────────────────────────────┤
│                                                         │
│                  SOFTWARE  WORLD                        │
│              (남는 공간 전부 · 절대 잘리지 않는다)          │
│                                                         │
╞══ 도구 판 하나 ═════════════════════════════════════════╡
│  문제 지표 / 고칠 문제+맥락 / 고치는 중 / 확인됨 / 해부도    │
╞══ 말하는 한 줄 · 54px ══════════════════════════════════╡
│  주어 ▸ 사람이 치는 말                              ⏎ QODE │
└─────────────────────────────────────────────────────────┘
```

- **판은 절대 두 겹으로 쌓이지 않는다.** 내용만 바뀐다.
- **World는 잘리지 않는다.** 판이 커지면 몸이 **다시 자리잡는다**(초점 재구성). 이전 판의 절단은 구조 결함이었고, 이 규칙이 그것을 없앤다.
- **선 굵기는 딱 두 가지.** 구조 경계 = 2px 먹선(판의 위 · 말하는 줄의 위) · 그 밖의 모든 구분 = 1px 실선. **상자는 하나도 없다.**
- **왼쪽 기준선 22px 하나.** 상단 이름 · 판 라벨 · 지표 번호 · 말하는 줄의 주어가 모두 같은 축에 선다.
- **타입 스케일 여덟 단계.** `30 / 19 / 17 / 15 / 13 / 12 / 10.5mono / 9.5mono`. 이 밖의 크기는 쓰지 않는다.
- **결의 굵기는 화면 픽셀 기준으로 고정한다** (`lineWidth = 0.95 / scale`). 축소해도 결이 희미해지지 않는다.

### 2.2 상단 한 줄 — 왼쪽은 정체, 가운데는 동사, 오른쪽은 렌즈

| 구역 | 문법 | 내용 |
|---|---|---|
| 왼쪽 | 13px 600 ink + 9.5px mono | `주문 서비스` · `문제 2` / `고치는 중 · 문제 2` / `확인됨` |
| 가운데 | **13px 600 ink** (유일한 동사) | `실행 ⌘R` → 실행 중이면 `실행 중 00:12 · 멈추기`(주의색) |
| 오른쪽 | 9.5px mono ink3, `·` 로 구분 | `시간 · 연결 · 깊이` — 열린 렌즈는 ink + **상단 실선에 닿는 2px 밑줄** |

**`가져오기`는 상단에서 내렸다.** 그것은 동사도 렌즈도 아니고 **비어 있을 때의 행동**이다 → 런처와 `연결` 렌즈로 옮겼다. 남은 넷은 **동사 하나 + 렌즈 셋**으로 일관된다. 이것이 “상단이 의도적으로 보이는가”에 대한 답이다.

### 2.3 말하는 한 줄 — 주어는 제품이 쓴다

> 채팅 상자가 아니다. **주어가 미리 적혀 있는 문장 한 줄**이다.

```
결제 요청 ▸ 이거 고쳐줘|                              ⏎ QODE
```

- 줄은 늘 **지금 말을 거는 대상**을 먼저 적고 있다. 아무것도 집히지 않았으면 주어는 `주문 서비스`다 — **주어가 비는 일은 없다.**
- 사용자는 뒤에 술어만 더한다. `고쳐줘` 세 글자로 완결된 문장이 화면에 존재한다.
- **“여기”를 타이핑할 필요가 없는 이유가 화면에 보인다.** 이것이 “여기 고쳐줘”를 마술이 아니라 구조로 만드는 방법이다.
- **17px — 껍데기에서 가장 큰 글자.** 가장 중요한 행위가 가장 큰 무게를 갖는다.
- 상자 · 둥근 테 · 보내기 버튼 없음. `⏎ QODE` 는 **글자가 있을 때만** 오른쪽 끝에 나타난다.
- 유령 문구 `무엇을 바꿀까요?` 는 안내문이 아니라 **문장의 빈칸**이다. 05에서도 이 줄은 죽지 않는다.

### 2.4 문제 지표 — 번호가 World와 지표를 잇는다

> World의 **읽히는 지표(readable index)**. 사이드바도 이슈 트래커도 위젯도 아니다.

```
문제                                                      전부 2

1   결제 요청      응답이 늦어요 · 3번 중 2번
2   사용자 저장    가끔 목록이 비어요
```

- **번호가 연결선을 대체한다.** World의 어긋난 자리 옆에 `1` `2`가 서고, 아래 지표의 같은 번호가 그것을 사람 말로 읽는다. **화살표도 연결선도 필요 없다.**
- **World의 읽히는 순서 = 지표의 순서.** 이전 판의 순서 불일치를 없앤다.
- 열은 여덟 화면에서 고정된다 — 번호 `22`, 자리 이름 `46`, 사람 말 `178`. 가로로 정렬된 행은 **목차**로 읽히고, 세로 괘선을 넣은 두 칸은 대시보드로 읽힌다. 그래서 괘선을 죽였다.
- 집힌 행: 번호가 ink, 왼쪽 여백에 2px 먹선. 나머지 행은 ink4로 물러난다. **배경 칠 없음.**
- 최대 3행 · 넘치면 `전부 n` · **문제 0이면 판이 사라진다.**
- 자리 이름은 **집힐 때만** World에 뜬다. 지도와 범례의 관계다.

### 2.5 집힘 — 색이 아니라 빛이다

이전 판에서 실패와 집힘이 같은 모습이었던 것이 가장 큰 실패였다. 나눈다:

| | 무엇으로 말하는가 |
|---|---|
| **실패 · 주의** | 결의 거동(끊김 · 어긋남) + 상태색 |
| **집힘** | **나머지가 물러난다** — 몸 전체가 0.26~0.44로 내려가고, 그 자리만 온전한 밝기로 남는다 |

- 밝은 자리는 **타원 그라디언트로 부드럽게 번진다** — 테두리가 생기지 않는다. `테두리 없이 집히는 자리`라는 기존 원칙의 실제 구현이다.
- 집힌 자리에서만 `번호 + 이름`이 나타난다.
- 색은 그대로 상태 전용이다. **집힘은 색을 쓰지 않는다.**

### 2.6 맥락 — 판 안의 접힌 한 줄

별도의 띠를 만들지 않는다. 고칠 문제 아래, **같은 판 안에서 1px 실선 하나로 구분된 한 줄**이다.

```
준비됨   결제 요청  외부 결제 호출  최근 실행 기록 3건        준비한 내용 보기
```

양식이 아니고, 기본값이며, 틀렸을 때만 펼친다.

### 2.7 결과 — 상자도 배지도 없다. 문장과 계측이다

`확인됨` 을 **판의 이름 자리**로 올렸다 — 다른 판이 `문제` · `고칠 문제` · `고치는 중` 을 쓰는 그 자리다. 배지도 토스트도 사라진다.

```
확인됨                                                  남은 문제 1

결제 요청이 달라졌어요.
외부 결제 호출에 재시도와 대기 시간을 넣었습니다.
같은 요청 20회 · 모두 3초 이내 · 실패 0
무엇이 바뀌었나요?     이전으로 돌아가기
```

- “되었나?”에 **세 갈래로** 답한다 — 몸이 가라앉고, 판의 이름이 `확인됨`이 되고, 문장 아래에 **계측**이 붙는다.
- `어떻게 확인했나요?` 를 죽였다 — 계측 줄이 이미 그 답이다. 링크 셋 → 둘.
- `이전으로 돌아가기` 에 `past #5B6B84` 를 쓴다. 정의만 되어 있던 색에 **의미를 준다** — 그것은 지난 평형이다.
- 결과가 있는 동안 지표는 판을 내어준다. 남은 문제 수는 상단과 판의 오른쪽 끝에 그대로 있으니 **잃는 정보가 없다.**

### 2.8 깊이 — 레일을 버리고 해부도로

> 파일은 있다. IDE로는 돌아가지 않는다.

**죽인 것:** 오른쪽 352px 세로 레일 · `파일 코드 API 스키마 증거` 탭줄 · 트리 · 폴더 삼각형 · 아이콘 · 열린 파일 강조. 이것들이 IDE의 문법이고, 하나라도 남으면 IDE로 읽힌다. 특히 **세로 레일**이 그렇다.

**한 것:**

- **World는 통째로 남는다.** 축소해서 전부 보이게 하고, 집힌 자리만 밝다. **몸을 절단하지 않는다** — 절단은 “깊이”가 아니라 “고장”으로 읽혔다.
- 해부도는 **아래에서 가로로** 열린다. 머리에 `세션 유지` 20px, 그 옆에 `이 자리를 이루는 것 · 방금 실행에서 실패 3회`.
- 세 단이 **한 번에** 보인다 — `파일` · `바깥과의 관계` · `증거`. 탭이 없으므로 무엇을 골라야 할지 묻지 않는다.
- 바닥에 `이 자리 밖의 것은 여기 없습니다.` 이것이 이 화면의 논지이므로 12.5px로 올렸다.
- 말하는 줄은 그대로, 주어는 `세션 유지`. **자리를 벗어나지 않았다는 증거**다.

### 2.9 런처 — 카드 갤러리를 버리고 몸의 목록으로

- 3열 카드 갤러리를 죽였다. 행 하나 = **몸(262×102) · 이름 · 사람 말 · 시간 · 문제 수**.
- **문제 수는 오른쪽 끝에 정렬된 숫자 열**이 된다. 한 번의 눈짓으로 어느 Software가 아픈지 읽힌다 — 런처가 할 일은 이것이다.
- `새로 가져오기` 는 3행 리스트에서 **한 줄의 세 단어**로 접었다.
- `JUQODE` 워드마크와 `Developers Code. Vibe Coders Qode.` 한 줄. 제품의 논지는 여기에만 놓는다.
- 축소판의 결 굵기를 화면 기준으로 고정해서 **낙서가 아니라 몸으로** 보이게 했다.

---

## 3. World와 사람 말 — 추상은 해석 능력을 요구하지 않는다

어떤 화면에서도 결만 보고 추론하게 두지 않는다. **언어 통로 세 개가 항상 열려 있다.**

| 통로 | 자리 | 예 |
|---|---|---|
| 상태 한 마디 | 상단 왼쪽 (고정) | `문제 2` · `고치는 중 · 문제 2` · `실행 중` · `확인됨` |
| 사람 말 한 줄 | 판의 지표 | `응답이 늦어요 · 3번 중 2번` |
| 지금 말을 거는 대상 | 말하는 줄의 주어 | `결제 요청 ▸` |

여기에 **번호**가 더해져 World와 언어를 잇는다. 자리 이름은 집혔을 때 World에 뜬다.

## 4. 여덟 화면 — 무엇을 증명하는가

| | 증명 |
|---|---|
| **01 Launcher** | 열기 전에 **어느 Software가 아픈지** 숫자 열 하나로 읽힌다 |
| **02 Workspace** | 상시 UI가 **상단 한 줄 · World · 판 하나 · 말하는 한 줄**뿐이다. World의 `1 · 2`가 지표의 `1 · 2`다 |
| **03 Problem → Focus** | 집힘이 **실패와 다른 모습**이다. 나머지가 물러나고 주어가 바뀐다 |
| **04 Qode · Context** | 화면의 문장이 `결제 요청 ▸ 이거 고쳐줘`다. 맥락은 접힌 한 줄 |
| **05 Working** | 진행률 막대 없음. 말하는 줄이 **살아 있다** |
| **06 Result** | 상자도 배지도 없이 `확인됨` · 문장 · 계측. 문제 **2 → 1** |
| **07 Run → Problem** | 실행이 관측으로 들어와 새 문제가 **1번**이 되고 주어가 그 자리로 바뀐다. 배지 대신 `방금` |
| **08 Deep View** | 파일 · 바깥과의 관계 · 증거가 다 있는데 **레일도 탭도 트리도 없다** |
