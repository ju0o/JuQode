## 0. 이번 단계에서 폐기한 것 — 점밭(Dot Field)

3R.1은 밀도를 **작은 정사각 표식의 밭**으로 표현했다. Founder 판정:

> **"점들이 쫙 나열된 느낌"**

그 판단이 옳았다. 표식을 뿌리는 것은 밀도를 **세는 것**이지 **보는 것**이 아니었고,
결과물은 소프트웨어가 아니라 **산점도**였다.

### 대체 원리

> **밀도는 표식을 더해서 만들지 않는다. 연속 공간을 나눠서 만든다.**

무거운 영역은 **더 잘게 나뉜다.** 100개의 의미 객체는 100개의 점이 아니라
**더 촘촘한 구조**가 된다. 이것이 3R.3의 단 하나의 결정적 변경이다.

| | 3R.1 (폐기) | 3R.3 |
|---|---|---|
| 밀도의 표현 | 표식 48개까지 뿌림 | **분할(subdivision)** |
| 100 객체 | 점 48개 (포화) | 칸 5개 (포화) |
| 몸당 요소 수 | 최대 380 | **13–25** |
| 읽히는 것 | 산점도 | **단면(section)** |
| 표식의 역할 | 지배적 | **경로 위 지점에만. 화면당 ≤6** |

## 1. Channel Ownership Table

> **채널이 두 가지를 뜻하기 시작하면 그림은 즉시 인포그래픽이 된다.**
> 이 표가 문법의 헌법이다.

| 채널 | 소유 | 의미할 수 있는 것 | 의미할 수 **없는** 것 |
|---|---|---|---|
| **세로 위치** | L1 | 사람으로부터의 거리 (표면 · 처리 · 저장) | 시간 · 순서 · 우선순위 |
| **가로 위치** | L1 | 관심사 구분 (lane) | 시간 · 순위 · 중요도 |
| **면적 · 비율** | L1 | 의미의 무게 | 개수 · 파일 수 · 줄 수 |
| **분할 정밀도** | L1 | 내부의 복잡도 · 풍부함 | 상태 · 확신 · 범주 |
| **선 (굵고 방향 있음)** | L2 | 이동 · 의존 · 핸드오프 | 구조 분할 |
| **선 굵기 (경로)** | L2 | 집약된 관계 수 (1 / 2–4 / 5+) | 중요도 |
| **경계 두꺼워짐 (Port)** | L2 + E1 | 바깥 접촉 · **비가역 지점** | 범주 · 연동 목록 |
| **내부 톤 (`--sunk`)** | L3 | **지반의 단단함** — 안정 / 교란 | 중요도 · 범주 · 선택 |
| **윤곽 완결성** | L4 | 아는가 / 모르는가 | 심각도 · 우선순위 |
| **파선** | L4 | 미확인 · 모름 | 스타일 · 장식 |
| **색** | L3 + E1 | 상태 · 결과 | **범주. 절대 금지** |
| **운동** | L3 | 실제 평형 전이 | 분위기 · 생동감 · 로딩 |
| **해상도** | L5 | 의미 층위 | 배율 · 라벨 개수 |
| **불투명도** | **없음** | **예약. 쓰지 않는다** | — |
| **표식(정사각)** | L2 | 경로 위의 지점 · 원점 | **밀도. 금지** |

### 1.1 두 개의 절대 규칙

1. **색은 범주를 뜻하지 않는다.** 다섯 개의 몸은 전부 같은 잉크로 그려진다.
   프로젝트 유형별 색 코딩은 존재하지 않는다.
2. **불투명도는 비워 둔다.** 가장 남용되는 채널이므로 예약한다.
   3R.1이 밀도 포화에 opacity를 썼다가 *100개가 40개보다 옅어 보이는 역전*을 만들었다.

### 1.2 선의 위계 — 하나의 색, 세 개의 굵기

구조는 전부 `--hair` 하나로 그린다. 위계는 **굵기로만** 만든다.

```
층 구분 (band)      2px    --hair     1차 — 깊이 축. 가장 먼저 읽힌다
관심사 구분 (lane)  1px    --hair     2차
분할 (cell)         0.75px --hair     3차 — 밀도

경로 (path)         2.2px  --ink2     구조보다 어둡고 굵다 + surface halo 5.5px
경계 (boundary)     2px    --ink      몸의 한계
```

**경로가 분할선 위를 지날 때 `--surface` halo를 먼저 깐다.** 흰 도랑이 생기고,
그 도랑이 *이동*과 *벽*을 구조적으로 갈라 놓는다. 이것이 L1/L2 충돌의 유일한 해법이다.

## 2. Software Body

### 2.1 정의

> **Software Body = 하나의 경계 안에서, 깊이 축을 따라 나뉘고,
> 인과가 관통하고, 몇 군데에서 바깥과 닿는 연속 공간.**

닮으면 안 되는 것: 대시보드 · 카드 그리드 · 노드 그래프 · 아키텍처 다이어그램 ·
ERD · 마인드맵 · 화이트보드 · 파일 탐색기 · 도시/게임 월드 · **산점도**.

닮아도 되는 것: **단면(section)**. 건축 단면도나 지질 단면처럼,
층이 있고 두께가 다르고 무언가가 관통한다.

### 2.2 구성 요소 (4개. 3R.1에서 개수 유지, 3번의 내용만 교체)

| # | 요소 | 규격 |
|---|---|---|
| 1 | **BOUNDARY** | 2px `--ink`. 미완성이면 1px `--ink4` dashed. 몸의 한계이자 **되돌릴 수 있음의 한계** |
| 2 | **REGION** | band(세로, 깊이) × lane(가로, 관심사). 질량이 두께를 정한다 |
| 3 | **PARTITION** | 질량에서 계산된 내부 분할. **밀도의 유일한 표현.** (구 Density Field 대체) |
| 4 | **PATH** | 인과. 직교. 방향 표식 1개. Port에서 경계를 통과한다 |

JUNCTION과 LOOP는 여전히 **PATH의 위상**이지 새 요소가 아니다.

### 2.3 분할 알고리즘 (결정적. 난수 없음)

```
subdivide(rect, n):
  k = cellCount(n)
  cells = [rect]
  while cells.length < k:
     c = 면적이 가장 큰 칸
     axis = (첫 분할이고 c.h >= 40) ? 가로       ← 몸은 표가 아니라 층으로 나뉜다
          : (c.w/c.h > 1.5)        ? 세로
          : (c.h/c.w > 1.5)        ? 가로
          :                          번갈아
     t = RATIOS[i++ % 10]        RATIOS = [.58 .44 .62 .48 .55 .41 .60 .47 .53 .45]
     c 를 t 비율로 자르고 그 자른 선을 분할선으로 기록
```

| n (의미 객체) | 칸 수 | 읽히는 것 |
|---|---|---|
| 0–1 | 1 (분할 없음) | 단순하다 |
| 2–4 | 2 | 나뉘어 있다 |
| 5–12 | 3 | 구조가 있다 |
| 13–28 | 4 | 복잡하다 |
| **29+** | **5 (포화)** | **매우 복잡하다** |

**질량이 2 미만인 lane은 분할하지 않는다.** 복잡한 곳만 복잡해 보여야 한다.

**포화 규칙:** cap을 넘어도 선을 더 그리지 않는다. 29와 300은 FAR에서 구분되지 않고,
**그 구분은 FAR의 사실이 아니다.** 정확한 수는 MID에서 mono로만 나온다.

**결정성 = 공간 기억.** 같은 입력은 같은 그림을 만든다.
힘 기반 배치 없음 · 난수 없음 · 재렌더 시 흔들림 없음.

### 2.4 첫 분할이 가로인 이유

세로 분할을 먼저 하면 몸이 **열(column)** 로 나뉘고 즉시 **표**로 읽힌다.
실제로 그렇게 됐다가 고쳤다. 가로를 먼저 자르면 **층(stratum)** 이 생기고,
그것이 깊이 축이라는 지배 축과 같은 방향이라 **단면**으로 읽힌다.

## 3. Mass Rules

### 3.1 v0.1 결정적 공식

```
mass(object) = 1
             + 2  if  경계를 통과하는 접촉을 가진다        (Port)
             + 1  if  줄기 경로(band를 넘는 경로) 위에 있다
             + 2  if  비가역 등급이 irreversible / destructive
             + 1  if  최근 Qode의 대상이었다
             + 2  if  사용자가 명시적으로 중요하다고 표시했다

범위 1–9.  region mass = Σ object mass
```

### 3.2 입력이 아닌 것 (HARD)

```
파일 수 · LOC · 함수 수 · 커밋 수 · 폴더 깊이
```

**상관관계가 있을 뿐이며, 상관을 인과로 쓰면 P3(정직) 위반이다.**
30줄짜리 결제 로직이 3,000줄 CSS보다 무겁다. 이 규칙을 어기면 문법 전체가 거짓말이 된다.
→ **코드 리뷰 강제 항목**

### 3.3 질량이 통제하는 것 / 하지 않는 것

| 통제한다 | 통제하지 않는다 |
|---|---|
| band 두께 (세로 비율) | 색 |
| lane 폭 (가로 비율) | 상태 |
| 분할 정밀도 | 확신 |
| 무게중심 | 선택 여부 |

**무게중심(center of mass)** 은 1급 읽을거리다 — 아래로 내려가면 데이터 중심,
경계 쪽으로 가면 통합/인프라 중심.

## 4. Causality Rules

**Canon 부록 B가 지목한 가장 취약한 법칙.** 제약이 곧 법칙의 본체다.

### 4.1 무엇이 PATH를 얻는가

> **사람이 한 문장으로 말할 수 있는 이동만 PATH가 된다.**
> "요청이 들어와서 로그인을 거쳐 저장된다."

### 4.2 무엇이 PATH를 얻지 못하는가 (HARD)

```
import · 함수 호출 · 타입 의존 · 상속 · DI 와이어링 · 파일 참조 · 빌드 의존
```

이것들은 기술 사실이지 사람이 신경 쓰는 이동이 아니다. **DEEP에서만 존재한다.**

### 4.3 개수별 동작 — 화살표 숲 방지

| 의미 관계 수 | FAR | MID |
|---|---|---|
| **≤5** | 전부 그린다 | 전부 |
| **6–20** | **줄기만** — band 또는 경계를 넘는 경로만 | 진입한 region 안의 경로 추가 |
| **21–100** | 줄기만 + **평행 경로 집약** | region 내부도 집약 적용 |
| **100+** | 동일 (줄기 수는 구조적으로 적다) | 동일 |

**줄기(trunk)의 정의: band 경계 또는 Software 경계를 넘는 경로.**
이 정의가 FAR의 경로 수를 구조적으로 상한한다 — band는 3개뿐이므로 줄기도 몇 개뿐이다.
보드의 다섯 몸은 전부 **경로 5–6개**다.

**집약(aggregation):** 같은 두 region을 잇는 평행 경로는 하나로 합치고 굵기로 수를 표현한다.

| 관계 수 | 선 굵기 |
|---|---|
| 1 | 1.4px |
| 2–4 | 2.2px |
| 5+ | 2.8px |

같은 규칙이 Port에도 적용된다 — 보드의 AGENT에서 접촉 3개가 **하나의 접근 경로**를 공유한다.
그것이 집약 규칙이 실제로 동작하는 모습이다.

### 4.4 전파 깊이

| | v0.1 | 이후 |
|---|---|---|
| 표시 깊이 | **1** | 2 |
| 정지 조건 | Software 경계 | 동일 |
| 표현 | **정적 상태** (닿는 범위가 함께 밝아진다) | 동일 |

**전파는 애니메이션이 아니다.** 파문 효과 금지.

### 4.5 회로는 사각형으로 그리지 않는다

닫힌 경로를 4구간 직사각형으로 그리면 **칸(cell)으로 오독된다.**
실제로 그렇게 됐다가 고쳤다.

> **회로는 최소 5구간의 계단(staircase)으로 그린다.**

직사각형은 벽이고 계단은 이동이다. 이 규칙 하나가 L1/L2 혼동의 마지막 구멍을 막는다.

## 5. Equilibrium States

**진행률 바 없음 · 퍼센트 없음 · 스피너 없음 · 초록 체크 없음 · 상태 카드 없음.**
**몸 자체가 상태를 말한다.**

| 상태 | 지반 톤 | 분할선 | 경로 | 색 | 무엇이 보이는가 |
|---|---|---|---|---|---|
| **SETTLED** | 없음 (흰 바탕) | 실선 | 실선 `--ink2` | — | 고요하다 |
| **DISTURBED** | **영향 영역만 `--sunk`** | 실선 | 변화 없음 | — | 그 영역의 지반이 파였다 |
| **SETTLING** | 영향 영역 `--sunk` | **영향 lane만 파선** | **새 경로 파선 + `--attention`** | attention | 생겼으나 굳지 않았다 |
| **SETTLED′** | 없음 (복귀) | 실선 | **새 경로도 같은 실선** | — | 굳었다. 질량 반영 |
| **UNSETTLED** | 영향 영역 연한 실패톤 | 실선 | 실패 구간 `--failure` dashed | failure | 새 평형에 못 갔다 |
| **UNKNOWN** | 없음 | **윤곽만 · 만나지 않음** | 없음 | — | 안을 모른다 |

### 5.1 지반 은유가 하는 일

`--sunk` 톤은 배경색이 아니라 **"이 영역은 지금 단단한 땅이 아니다"** 는 뜻이다.
그래서 전역 스피너가 필요 없다 — **교란은 언제나 국소적**이고, 나머지 화면은 조금도 변하지 않는다.

### 5.2 SETTLING이 이 문법의 핵심이다

다른 도구가 초록 체크를 주는 지점에서 JuQode는 **파선과 attention으로 붙잡아 둔다.**
`SETTLING`과 `SETTLED`의 차이는 세 채널이 동시에 다르다:

```
톤 있음  +  파선  +  attention        vs        톤 없음  +  실선  +  ink2
```

**세 채널이 함께 바뀌므로 색맹·저대비 환경에서도 구분된다.**

### 5.3 증거만이 ④를 만든다

`SETTLING → SETTLED′` 전이의 **유일한 원인은 증거**다.
시간 경과 · 에이전트의 "완료" 주장 · 사용자의 확인 클릭 — 어느 것도 이 전이를 일으키지 않는다.

| 증거 | 결과 |
|---|---|
| 테스트 통과 · 빌드 성공 · 동작 관측 | `SETTLED′` |
| 증거를 얻을 수 없음 | `UNKNOWN` |
| 증거가 주장과 모순 | `UNSETTLED` |

증거의 **내용**은 캔버스에 오지 않는다. Contextual Surface와 DEEP에만 있다.
캔버스에는 **결과 상태**만 온다.

## 6. Empty vs Unknown

Canon이 남긴 최우선 미해결 문제. **해법은 두 축이다.**

| | EMPTY | UNKNOWN |
|---|---|---|
| **경계의 확정성** | 1px `--ink4` **dashed** | 2px `--ink` **solid** |
| **내부** | **완전히 비어 있음** | **분할선이 있으나 서로 만나지 않음** |
| **층 구분** | 없음 | 있으나 파선 `--ink4` |
| **원점 표식** | **있음 (12px)** | 없음 |
| **의미** | 아직 아무것도 없다 — 그리고 그걸 안다 | 무언가 있다 — 그런데 못 따라간다 |
| **불확실성** | **0 (완전한 앎)** | **최대** |

### 6.1 구현 규칙

```
EMPTY    boundary: 1px ink4 dashed(5 5) · 내부 렌더링 없음 · 중앙 12px ink 정사각
UNKNOWN  boundary: 2px ink solid
         band/lane 구분: 1px ink4 dashed(7 5)          ← 추론했으나 확정 아님
         분할선: 양끝 24% 잘라낸 1px ink4 dashed(5 4)   ← 칸이 닫히지 않는다
```

**양끝을 잘라내는 것이 이 표현의 전부다.** 선이 만나지 않으면 칸이 닫히지 않고,
칸이 닫히지 않으면 **구조를 따라갈 수 없다**는 것이 라벨 없이 읽힌다.

### 6.2 왜 이것이 IDE가 줄 수 없는 화면인가

파일 트리는 **항상 뭔가를 아는 척한다.** 폴더 목록은 구조가 아니지만 구조처럼 보인다.
JuQode의 UNKNOWN 화면은 *"여기 구조가 있다. 나는 그것을 따라갈 수 없다"* 를 말한다.
그것이 P3(정직)의 시각적 실현이다.

### 6.3 부분적 이해 — 같은 몸 안에 섞일 때

한 몸 안에서 어떤 lane은 확인됐고 어떤 lane은 모를 수 있다.
**lane 단위로 위 규칙을 적용한다.** 경계는 몸 전체에 하나이므로 solid를 유지한다.
→ 이 혼합 상태의 가독성은 **Founder Gate 확인 항목**이다 (§12 F2).

## 7. Observation / Semantic Zoom

### 7.1 단계별 정의

| | **FAR** | **MID** | **NEAR** | **DEEP** |
|---|---|---|---|---|
| **보이는 요소** | 경계 · band · lane · 분할 · 줄기 · Port | 진입 region의 분할이 **개별 객체로 해상** · region 내 경로 | 객체 하나의 **지역 경로** · 단계 표식 | 캔버스 아님 |
| **라벨 예산** | **≤7** | **≤14** | **≤22** | 제한 없음 |
| **인과 깊이** | 줄기만 | region 내부 + 줄기 1단계 | 지역 전부 | — |
| **불확실성 해상도** | `UNKNOWN`만 | + `미확인` | 전부 | 증거 원문 |
| **Qode 대상** | region · Port | 객체 · 경로 | 단계(step) | 없음 |
| **맥락 정보** | 소프트웨어 전체 | 진입한 region | 선택한 객체 | 파일 · diff · 스키마 |

### 7.2 전이 규칙

- **DOM을 언마운트하지 않는다.** 질량 값을 바꾸고 좌표를 재계산한다
- **MID 진입 = 대상 lane 질량 × 배수.** 형제 band는 FLOOR로 붕괴해 **띠로 남는다**
  → 깊이 감각이 유지되므로 breadcrumb이 필요 없다
- **들어갈수록 바깥의 분할이 사라지고 안쪽의 구조가 나타난다**

### 7.3 잉크 규칙 — Canon 표현의 정밀화

Canon은 "잉크 총량이 거의 일정하다(CONSTANT INK)"고 썼다. 보드에서 실측한 결과:

```
FAR   구조선 25 + 경로 5  = 30 요소
MID   구조선  8 + 경로 2 + 표식 5 = 15
NEAR  구조선  4 + 경로 4 + 표식 4 = 12
```

총량은 **일정하지 않고 줄어든다.** 따라서 규칙을 정확히 다시 쓴다.

> **NO INK ACCUMULATION — 잉크는 누적되지 않는다.**
> 들어갈 때 총량은 일정하거나 **줄어든다.** 늘어나면 위반이다.

막으려는 실패 모드는 *누적*이었고, 감소는 오히려 옳다 —
대상이 적어지고 각각이 자세해지는 것이 해상(resolution)이기 때문이다.
**Canon의 개념은 유지하고 표현만 정확하게 고친다.**

## 8. Reversibility / Ports

### 8.1 경계는 되돌릴 수 있음의 경계선이다

그러나 **경계를 넘는 모든 것이 똑같이 비가역인 것은 아니다.** 3등급으로 나눈다.

| 등급 | 예 | 시각 | 저항 |
|---|---|---|---|
| **읽기 통과** | 조회 API · 모델 질의 · 파일 읽기 | Port `--ink`, 경로 `--ink2` | 없음 |
| **보상 가능** | 주문 생성 · 임시 게시 · 취소 가능한 결제 | Port `--ink`, 경로 `--ink2` **굵게** | 실행 전 대상 표시 |
| **비가역** | 메일 발송 · 결제 확정 · 공개 게시 · 권한 변경 · 운영 데이터 삭제 | **Port `--attention`** + 경로 `--attention` | 대상 표시 + 사람의 확인 + (파괴적이면) 의도의 재진술 |

**색이 여기서만 등급을 얻는다.** 이것은 범주가 아니라 **결과**이므로 채널 규칙에 부합한다.

### 8.2 사용자가 라벨 없이 알아야 하는 것

> **"이 선을 넘으면 결과가 밖으로 나간다."**

경계 위 마디의 위치와, 그 마디로 향하는 경로의 색이 그것을 말한다.
보안 대시보드 미학(자물쇠 · 방패 · 경고 배너)은 쓰지 않는다.

### 8.3 금지

Integration Card · 연동 목록 패널 · Port 툴팁 카드 · 떠 있는 외부 서비스 로고.
**Port는 경계선이 두꺼워지는 마디이지 그 위에 얹힌 물건이 아니다.**

## 9. Growth

### 9.1 자람이 바꾸는 것

| 축 | 시각 결과 |
|---|---|
| 질량 | band/lane 비율 → **실루엣이 바뀐다** |
| 분할 | 칸이 늘어난다 → **촘촘해진다** |
| 위상 | 구간 삽입 · 분기 · **회로가 닫힌다** |
| 도달 | Port가 생기거나 굵어진다 |
| 경계 | dashed `--ink4` → solid `--ink` (첫 Qode) |

### 9.2 기준 사례 A — EMPTY → 첫 Qode (`로그인부터 만들어줘`)

```
① 경계가 실선으로 굳는다        — 몸이 하중을 받기 시작한다
② 세 층이 처음으로 두께를 갖는다
③ 표면에 첫 분할선이 생긴다      — 원점이 구조가 되었다
④ 위 경계에 첫 접촉이 열리고 거기서 줄기가 내려온다
```

**빈 캔버스에 카드가 나타나는 것이 아니다.**

### 9.3 기준 사례 B — 재시도 (`로그인 실패하면 다시 시도하게 해줘`)

```
①→② 영향 lane의 지반이 파인다
②→③ 구간이 삽입되고 회로가 닫힌다 (파선 + attention)
③→④ 증거 도착 → 실선으로 굳고 · 처리 층이 두꺼워지고 · 분할이 촘촘해진다
```

### 9.4 공간 기억 보존

분할은 결정적이고 band/lane 순서는 고정이므로,
**질량이 변해도 기존 구조는 제자리에서 비율만 바뀐다.** 재배치가 일어나지 않는다.

## 11. Honesty — UNKNOWN의 규격

### 11.1 판정 규칙

| 상황 | 상태 |
|---|---|
| 증거가 있고 일관됨 | `확인됨` |
| 구조는 읽었으나 검증 안 됨 | `미확인` |
| **읽었으나 의미를 확정 못 함** | **`UNKNOWN`** |
| **관측하지 않음** | **`UNKNOWN`** (L5 — 관측하지 않은 것은 계산하지 않는다) |
| 증거가 서로 모순 | `UNSETTLED` |

**추론으로 UNKNOWN을 메우지 않는다.** 그럴듯한 구조를 그려 넣는 것은 P3 위반이다.

### 11.2 UNKNOWN은 항상 두 가지를 갖는다

```
① 무엇을 모르는가        → 캔버스 (윤곽만 · 만나지 않는 선)
② 무엇이 있으면 알 수 있는가 → Contextual Surface (캔버스 텍스트 아님)
```

②가 없으면 정직함이 무력함이 된다. Canon E2 완화 규칙.

### 1. 렌더 엔진 (순수 함수 3개. 가장 먼저.)

  // w = 0.06 + 0.94*(m/Σm) ;  h = total*w/Σw

### 2. 데이터 모델

```ts
type Band = 'surface' | 'logic' | 'data'
type Truth = 'settled' | 'disturbed' | 'settling' | 'unsettled' | 'unknown'

interface Software {
  name: string
  shell: 'firm' | 'provisional'      // solid ink / dashed ink4
  bands: [Region, Region, Region]     // 항상 3개. 질량 0이어도 존재
  paths: Path[]
  ports: Port[]
}
interface Region { id: Band; label?: string; lanes: Lane[] }
interface Lane {
  id: string; mass: number; objects: number; label?: string
  truth: Truth                        // lane 단위로 상태를 가진다
}
type Anchor = [Band, number, number]  // fx, fy = 0..1
interface Path {
  id: string; points: Anchor[]; mark?: number
  weight: 1 | 2 | 3                   // 집약된 관계 수 → 1.4 / 2.2 / 2.8px
  truth: Truth
  loop?: boolean                      // true면 최소 5구간 계단으로 라우팅
}
interface Port {
  id: string; edge: 'top'|'right'|'bottom'|'left'; at: number
  weight: 1|2|3; label?: string
  reversibility: 'read' | 'compensatable' | 'irreversible'
}
```
