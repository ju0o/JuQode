Software Physics Canon

이것은 제품 화면이 아니다. 법칙의 참조 카드다. 아래 그림들은 UI 시안이 아니라 각 법칙이 소유한 시각 채널을 하나씩 분리해 보여준다. 전체 명세는 SOFTWARE_PHYSICS_CANON.md에 있다.

왜 법칙이 필요한가. 표상을 세 번 교체했지만 세 번 다 도표로 읽혔다. 도표와 소프트웨어의 차이는 선의 모양이 아니다 — 도표는 아무 법칙도 따르지 않는다. 법칙은 장식이 아니라 제약이다: 어떤 채널이 무엇을 의미할 수 있고 무엇을 의미할 수 없는지를 정한다.

01 · THREE LAYERS

믿음 · 행동 · 통제

층을 섞지 않는다. 믿음은 JuQode가 소프트웨어에 대해 무엇을 믿는가, 행동은 소프트웨어가 인터페이스 안에서 어떻게 움직이는가, 통제는 결과가 큰 행동을 어떻게 다루는가다. Becoming은 믿음이라서 물리 법칙에서 강등했고, Responsibility는 윤리라서 물리에서 빼냈다.

A · 믿음Philosophy
P1BECOMING소프트웨어는 완성되지 않는다 — 완성도 지표가 존재하지 않는다
P2ABSORPTION복잡함은 JuQode의 것이다 — 파일·브랜치·환경변수는 Primary UI에 없다
P3HONESTY모르는 것은 모르는 채로 남는다 — UNKNOWN은 1급 상태다
B · 행동Physics
L1MASS의미가 자리와 크기를 만든다 · 파일 수가 아니다
L2CAUSALITY모든 것은 어디선가 와서 어딘가로 간다 · 전파는 깊이와 경계에서 멈춘다
L3EQUILIBRIUMQode는 작업이 아니라 평형 사이의 이동이다
L4UNCERTAINTY앎은 부분적이다 · 원래 이름 ENTROPY는 기각했다
L5OBSERVATION주의가 해상도를 정한다 · 양자역학이 아니라 지도학이다
C · 통제Ethics
E1REVERSIBILITY경계 밖으로 나간 것은 되돌릴 수 없다 · 결과가 저항을 정한다
E2EVIDENCE주장은 사실이 아니다 · 증거만이 평형을 회복시킨다

02 · CHANNEL EXCLUSIVITY

하나의 법칙은 하나의 채널만 소유한다

이 규칙 하나가 인포그래픽이 되는 것을 구조적으로 막는다. 아래 여섯 그림은 각 법칙이 소유한 채널을 그 채널만으로 그린 것이다. 가장 중요한 결과: 범주는 위치와 면적을 얻고, 색은 얻지 못한다. 색은 오직 결과와 상태만 의미한다.

L1
MASS
면적 · 위치
층의 두께가 곧 의미의 무게다. 색도 아이콘도 쓰지 않는다.
금지 — 중요도를 색으로 칠하는 것. 질량을 파일 수로 계산하는 것.
L2
CAUSALITY
선 · 방향 · 경계 통과
들어오고 · 변하고 · 되돌아오고 · 나간다. 경계를 통과하는 선이 곧 Port다.
금지 — 함수 호출 단위로 그리는 것. 전파 깊이 무제한. 화살촉 남발.
L3
EQUILIBRIUM
렌더링 자체의 안정성
교란된 영역만 안정성을 잃는다. 나머지 화면은 그대로 고요하다.
금지 — 전역 스피너 · 진행률 바 · 로딩 셔머. 화면 전체가 흔들리는 것.
L4
UNCERTAINTY
모서리 품질 · 내부 채움
모름은 윤곽만 있고 내부가 없다 — "무언가 있지만 안을 모른다"가 라벨 없이 읽힌다.
금지 — 경고 뱃지 · 노란 삼각형 · 4단계 이상의 확신 등급. 상시 노출.
L5
OBSERVATION
해상도
톤이 표식으로, 표식 하나가 경로로 해상된다. 잉크가 누적되지 않는다.
금지 — 확대가 라벨 추가가 되는 것. 관측하지 않은 것을 발명하는 것.
E1
REVERSIBILITY
경계 기준 위치 + 색
경계선은 되돌릴 수 있음의 경계선이다. Port는 연동이 아니라 비가역이 발생하는 지점이다.
금지 — 모든 것에 확인 모달. 색을 범주 구분에 쓰는 것.

03 · QODE STATE MODEL

다른 도구가 초록 체크를 주는 지점에서, JuQode는 멈춰 선다

SETTLING이 이 모델의 전부다. 코드가 써졌다는 것은 완료가 아니다. 증거가 도착해야 평형이 회복되고, 그때에만 Software Time에 점이 찍힌다. 그래서 되돌아갈 수 있는 곳은 언제나 확인된 상태다 — "돌아갔더니 거기도 깨져 있더라"가 구조적으로 불가능해진다.

상태뜻몸에서일반 에이전트 도구는
SETTLED안정. 지금 형태가 곧 사실이다고요함. 실선같음
DISTURBED대상 영역의 안정성이 유예됐다영향 영역만 파선전역 스피너
SETTLING변경됐으나 아직 확인되지 않았다새 구조 + attention완료 처리
SETTLED′확인됐다. 새 평형고요함 회복 · 시간축에 점커밋 하나
UNSETTLED확인 실패. 이전 평형은 유효failure + 이전 참조 유지에러 로그
UNKNOWN확인할 수 없었다윤곽만조용히 완료

04 · THE HARD PROBLEM

Empty와 모름은 반드시 달라 보여야 한다

이 Canon이 만든 가장 어려운 시각 문제다. 둘 다 "내부에 아무것도 그리지 않는" 상태인데, 의미는 정반대다. Empty는 완전히 아는 상태이고, 모름은 전혀 모르는 상태다. 이 둘이 같아 보이면 P3(정직)이 무너진다.

질량 0 · 불확실성 0
EMPTY
경계는 파선 — 아직 하중을 받지 않았다. 가운데 원점은 첫 번째 약속이다. 희미한 두 선이 깊이 축을 예고한다.
Empty는 결핍이 아니라 완전히 알려진 유일한 평형이다. 그래서 조용해야 한다 — 온보딩 체크리스트는 "당신은 아직 부족하다"는 잘못된 메시지다.
질량 있음 · 불확실성 최대
모름 (UNKNOWN)
경계는 실선 — 파일이 있으니 무언가는 확실히 존재한다. 영역의 윤곽은 그리되 내부를 그리지 않는다.
화면이 라벨 없이 말한다 — "여기 무언가 있다. 나는 아직 그 안을 모른다." IDE는 이 화면을 줄 수 없다. 파일 트리는 항상 뭔가를 아는 척한다.
OPEN · 3R.3에서 검증
위 두 그림은 제안이지 확정이 아니다.
구분의 축은 경계선의 성질(파선 ink4 / 실선 ink)과 내부 윤곽의 유무다. 작은 크기에서, 그리고 두 상태가 한 화면에 섞여 있을 때도 구분되는지는 아직 검증되지 않았다. 3R.3 Visual Grammar의 첫 과제로 지정한다.

05 · REJECTED

법칙이 되지 못한 것

기각 목록이 이 문서에서 가장 중요한 부분이다. 은유가 예측력을 갖지 못하거나 과학적으로 오해를 부르면 이름을 버렸다. 명료함이 영리한 용어보다 중요하다.

개념판정이유
ENTROPY개명 → UNCERTAINTY열역학 엔트로피는 무질서이지 무지가 아니다. 정보 엔트로피는 확률분포의 성질이지 "확인 안 됨"이 아니다. 유용한 아이디어는 살리고 틀린 이름을 버렸다
GRAVITY (인력)축소 → MASS상호 인력 시뮬레이션은 물리 엔진을 요구하고, 배치가 매번 달라져 공간 기억이 무너진다. 질량은 정렬하고 크기를 정할 뿐 끌어당기지 않는다
PENDULUM기각 (개념만 잔존)흔들리는 애니메이션은 가짜 움직임이다. 진자에서 가져온 것은 운동이 아니라 "멈추는 지점이 있다"는 개념뿐이고, 그것이 L3다
QUANTUM OBSERVATION프레이밍 기각JuQode에서 관측은 소프트웨어를 바꾸지 않는다. 렌더링만 바꾼다. 정직한 참조는 지도학의 일반화이고, 그쪽이 실제로 빌려 쓸 기법을 준다
THERMODYNAMICS 일반기각소프트웨어는 닫힌계가 아니다. 에너지 보존도 제2법칙도 성립하지 않는다. 은유가 예측력을 갖지 못한다
BECOMING (물리로)강등 → P1그 자체로는 행동을 규정하지 않는다. 믿음이다. 행동은 L1·L3가 담당한다
KAFKA법칙 아님 → 진단 렌즈시각 법칙으로 만들면 장식이 된다. "창조자가 자기 창조물에 소외된다"는 진단으로 쓸 때 가장 강하고, 그것이 P2가 됐다
철학자 인용 · 초상전면 기각철학으로 제품을 장식하지 않는다
Software Time = Git 커밋기각 → 평형의 나열커밋은 기술 사실이고 평형은 사람의 사실이다. 점의 개수가 수백 개에서 셀 수 있는 개수로 줄고, 돌아갈 수 있는 곳은 전부 확인된 상태가 된다

06 · MVP CANON CUT

v0.1은 물리 엔진을 만들지 않는다. 법칙을 지킬 뿐이다

법칙을 지키는 것과 법칙을 시뮬레이션하는 것은 다르다. v0.1에서 새로 보이게 되는 법칙은 셋뿐이다.
