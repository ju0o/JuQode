# Whole Product Interaction

> **Status:** Phase 3R.6 산출물. 표상(Realm)은 재설계하지 않는다 — 그 **주변 제품 전체**를 정한다.
> **Board:** [`whole-product-board.html`](whole-product-board.html) · 근거 이미지 `evidence/whole-product/`
> **Lovable credits spent:** 0. 구현하지 않는다.

## 1. 얼어붙는 한 줄

> **Software 자체가 주 입력면이다.**

입력은 텍스트 상자가 아니다. 하나의 Qode는 이렇게 만들어진다.

```
지금의 Software  +  지금 보고 있는 것  +  집은 자리  +  하려는 말
```

그래서 **“여기 좀 바꿔줘”** 가 성립한다 — JuQode가 *여기*가 어디인지 이미 알고 있기 때문이다.

```
SEE  →  POINT  →  SAY
```

## 2. 행동은 섞이지 않는다

전부 채팅으로 뭉개지 않는다. 여섯 가지는 **서로 다른 행동**이다.

| | 무엇인가 | 아닌 것 |
|---|---|---|
| **OPEN** | Software 세계로 들어간다 | Qode가 아니다 |
| **POINT** | 의미적 대상을 지정한다 | 그 자체로 Qode가 아니다 |
| **SAY** | 원하는 변화를 말한다 | 주 의도 입력 |
| **QODE** | 의도 + 대상 + 준비된 맥락 = 작업 단위 | 대화 한 턴이 아니다 |
| **RUN** | 실제 동작을 **관측**한다 | Qode가 아니다. 증거·교란을 만든다 |
| **IMPORT** | 정보를 넣는다(문서·이미지·JSON) | 소프트웨어 조작이 아니다 |
| **CONNECT** | 바깥 시스템과 관계를 만든다 | 구현이 필요해지면 그때 Qode가 된다 |

## 3. 화면의 골격

```
World  →  Focus  →  Instrument
```
가 아니라
```
Sidebar → Tab → Panel → Form
```
이 아니다.

상시로 존재하는 것은 **세 가지뿐**이다.

1. **Software World** — 화면에서 가장 큰 것. 나머지가 다 사라져도 남는다
2. **위쪽 한 줄** — 이름 · 상태 · 도구 세 글자(`시간` `실행` `깊이`)
3. **아래쪽 한 줄** — 입력

그 밖의 모든 것은 **필요할 때만 나타나는 얇은 판(instrument)** 이고, 일이 끝나면 사라진다.
파일 트리 · 터미널 · 좌측 사이드바 · 우측 속성 패널 · 긴 대화 기록 · 컨텍스트 관리자 — **없다.**

## 4. Launcher

주 언어는 **Software**이지 Repository·Folder가 아니다.

- 최근 Software는 **실제 몸의 축소판**으로 보인다. 이름보다 형태가 먼저 기억된다
- 각 항목이 말하는 것: 이름 · 최근 상태(확인됨/아직 확인 못 함) · 마지막 활동 · 미해결(모르는 곳 n)
- 새로 가져오기 세 줄: `이 컴퓨터에서` · `GitHub에서` · `새로 시작하기`
- 저장소 주소·브랜치·경로는 **한 단계 아래**에 있다
- 둥근 카드 벽을 만들지 않는다

## 5. Input

상시 채팅 패널이 아니다. 기본은 조용하고 납작한 한 줄이며, **지금의 초점을 안다.**

```
기본            원하는 걸 말해보세요.
자리를 집었을 때   로그인에 원하는 변화를 말해보세요.
흐름을 집었을 때   이 흐름에 원하는 변화를 말해보세요.
```

사용자는 맥락을 다시 말하지 않는다. 입력 문장이 바뀌는 것이 **선택 UI 전체를 대신한다.**
음성은 선택지로 열어 두되 필수로 만들지 않는다.

## 6. Context — 자동이 기본

> **Auto Preparation = Default.**

Context는 관리해야 하는 작업이 아니다. Qode를 만들면 JuQode가 알아서 준비하고, **접힌 한 줄**로만 보인다.

```
준비됨   로그인 · 세션 · 사용자 데이터 · 최근 인증 변경          준비한 내용 보기
```

펼치면 검사 · 잘못된 것 빼기 · 빠진 것 더하기가 가능하다.
**파일과 경로는 그보다 더 아래**에 있다. 의미가 먼저, 기술은 나중.

## 7. Run = 관측

실행은 입력이 아니라 **관측**이다. 실제 런타임 동작이 World에 들어온다.

```
실행 → 실제 동작 → 몸의 교란 → 실패한 자리가 드러남
     → "방금 실행에서 이곳이 실패했어요 — 세션 유지"
     → 사용자는 이미 그 자리를 보고 있다
     → "고쳐줘"  (두 글자로 Qode 성립)
```

이 경로가 이 제품의 가장 자연스러운 순환이다.

## 8. Import = Context Injection

파일은 JuQode의 일차 객체가 아니다. 끌어다 놓은 PDF·JSON·Markdown·스크린샷·API 문서는
**맥락 주입**으로 취급한다.

```
Stripe API 문서를 읽었습니다.  결제 영역과 연결할까요?
```

파일은 아래층의 기계적 사실로 계속 남는다.

## 9. Connect = 바깥과의 관계

경계(외부와 닿는 자리)를 집고 **외부와 연결하기**.
Stripe · Supabase · OpenAI · 직접 연결.
API 키 · 엔드포인트 · 헤더 · 환경변수는 **필요해진 순간에만** 나온다. 첫 경험이 설정 화면이 되지 않는다.

## 10. Result = 결과보다 몸이 먼저

에이전트의 긴 응답이 결과가 아니다. **몸이 새 평형으로 가라앉은 것**이 결과다.

```
로그인이 달라졌어요.                              확인됨
Google 로그인을 추가했고 기존 이메일 로그인은 그대로 두었습니다.

어떻게 확인했나요?   무엇이 바뀌었나요?   이전으로 돌아가기
```

증거 깊이: **보임 → 짧은 라벨 → 자세히 → 설명 → 원자료.** 묻는 사람에게만 열린다.
상태는 셋뿐이다 — `확인됨` · `문제 있음` · `아직 확인 못 함`.

## 11. Software Time

Git 히스토리를 기본으로 노출하지 않는다. **의미 있는 평형**만 나열한다.

```
지금
12분 전   Google 로그인 추가
1시간 전   Session Retry 수정
어제      첫 실행
```

한 점을 고르면 **World 자체가 그때 상태를 보여준다.** Git 정보는 깊은 층에 남는다.

## 12. Deep Technical View

파일과 코드는 지워지지 않았다. **깊은 해상도로 내려갔을 뿐**이다.

핵심 규칙: 깊은 뷰는 **항상 의미에 매달려 있다.**

```
로그인 — 실제 파일
이 자리를 이루는 것들 · 12분 전 변경
파일 · 코드 · API · 스키마 · 증거
…
이 자리 밖의 파일은 여기 없습니다.
```

IDE로 돌아가는 것이 아니다. 개발자는 닿을 수 있고, 비개발자는 지나갈 수 있다.

## 13. GUI 언어

World는 추상을 지고, **GUI는 통제를 진다.** 껍데기는 거의 보이지 않아야 한다.

D-054 유지 · radius 0 · 헤어라인 · 그라디언트 없음 · 글래스 없음 ·
큰 둥근 카드 없음 · 이모지 없음 · 일반 SaaS 미감 없음.
색은 상태에만 쓴다(`attention` 아직 확인 못 함 · `failure` 문제 · `past` 이전 평형).


## 15. 미해결

1. **Realm 간 전환.** Frontend(결)·Backend(바다)·Data 같은 서로 다른 현상이 한 Software 안에서
   어떻게 이어지는지는 이 단계에서 정하지 않았다. 이 판은 **하나의 Realm**으로만 그렸다.
2. **자리가 20개인 소프트웨어.** 3R.5의 수용량 한계(또렷한 자리 5~7개)가 그대로 남아 있다.
3. **여러 Qode 동시 진행.** 대기 표시는 넣었으나 병렬 작업의 화면은 설계하지 않았다.
4. **협업.** 한 사람 기준으로만 설계했다.
