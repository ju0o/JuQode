# 배치 25 — 체계적 돌연변이 스윕 (손으로 고르지 않은 것)

514 tests · e2e 3종. Canon 발견 없음.

지금까지의 돌연변이는 전부 **내가 고른 것**이었다 — 방금 고친 자리를 겨눈 것들이라, 아무도
쳐다보지 않은 코드는 한 번도 검사되지 않았다. 이번엔 **기계적으로 생성**했다.

## 어떻게 만드는가

`scripts` 가 아니라 스크래치의 도구다(제품에 남기지 않는다). 파일 하나를 받아 **주석을 벗긴
코드**에서만 자리를 찾는다(`tests/src.js` 의 렉서를 그대로 쓴다 — 주석 속 연산자를 바꾸면
아무 일도 안 일어나고 "살아남음" 으로 신고된다):

`===`↔`!==` · `&&`↔`||` · `>`↔`>=` · `<`↔`<=` · `return null/true/false` 뒤집기.

각 자리는 원본 파일에서 **유일하게 나타나는 문맥 45자**로 식별한다. 워커 넷이 저장소 사본을
하나씩 들고, 파일 하나만 패치해서 단위 스위트를 돌린다.

**멈추는 돌연변이는 죽은 것으로 친다** — 무언가를 깨뜨렸다는 뜻이니까. 다만 그게 90초씩
잡아먹어서 처음엔 420초 상한으로 두 시간짜리가 됐다. 90초로 줄였다.

## 진짜 구멍

### `measure()` 가 어느 트리를 재는지 아무도 확인하지 않았다

`.git` 건너뛰기를 뒤집어 **`.git` 만** 재게 해도 스위트 전체가 통과했다. 그러면 `19` §E 의
크기 상한이 실제 프로젝트에서 **조용히 안 걸린다** — 작업 트리가 아무리 커도.

이제 작업 트리로 상한을 넘기고, 같은 저장소가 넉넉한 상한에서는 통과하고, **보고된 크기가
`.git` 크기를 포함하지 않는 것**을 잰다(픽스처가 실제로 `.git` 을 갖고 있는지도 함께).

### 읽을 수 없는 루트가 거부되지 않을 수 있었다

`firstUnreadable` 이 `rel || '.'` 을 내는데 **루트의 `rel` 은 빈 문자열**이다. `|| '.'` 없이는
`''` 이 falsy 라 `refusal()` 이 통과시키고, 기준은 `add -A` 가 만든다 — 못 읽는 것을
**경고만** 하는 명령이다.

기존 테스트는 전부 파일이나 하위 디렉터리를 못 읽게 만들어서 `rel` 이 비지 않았다.
루트를 `0o111` 로 둬야 한다는 것도 이 테스트가 알려 줬다 — `0o000` 이면 `git --version` 이
먼저 실패해서 다른 이유로 거부된다.

### 중첩 저장소 원장의 `.git` 건너뛰기

기존 테스트의 파일이 중첩 저장소 **루트**에 있었다. 그 분기는 **하위 디렉터리 진입**을
정하므로 무관했다. 한 단계 아래 파일을 넣고, 원장에 `/.git/` 경로가 없는 것도 잰다.

### 닿을 수 없는 가드 — `확인됨` 강등

`buildChecked` 안의 세 줄은 `build()` 가 언제나 `sourceRef` 를 달기 때문에 **어떤 입력으로도
도달하지 않는다.** 그 줄들의 돌연변이가 전부 살아남았다.

가드는 **미래의 `build()`** 를 위한 것이라 남기되, `downgrade()` 로 빼내서 테스트가 `build()`
가 만들 수 없는 모양을 직접 건넬 수 있게 했다. 닿을 수 없는 가드는 아무도 확인할 수 없는 가드다.

### `system/status` 와 assistant 의 말이 매핑되지 않고 있었다

`toSignal` 의 `system/status` 분기는 **어느 쪽을 뒤집어도** 통과했다. 녹화 픽스처에 그 이벤트가
없고, 녹화가 이 매핑의 유일한 검사처였다 — **픽스처가 우연히 담지 않은 종류는 아무도 매핑하지
않고 있었다.**

이벤트 모양 → 신호 종류 표를 **적어 두었다**(파생하면 함수가 무엇을 하든 따라가서 실패할 수
없다). 아무도 안 적어 둔 `system` 하위 종류가 `raw` 인 것, 타입 없는 것도 `raw` 인 것,
assistant 의 텍스트가 `raw` 로 살아남는 것, 같은 메시지에서 `tool_use` 가 텍스트를 이기는 것.

### 부여가 **이름 붙인** 거부를 푼다 — 이름이 없으면 아무것도 안 푼다

기존 테스트는 전부 **첫 번째** 미해결 거부를 허용했다. 그래서 id 를 **완전히 무시하고**
"첫 미해결" 을 푸는 matcher 가 전부 통과했다.

D-116 이 여기 걸려 있다: 기록은 **사람이 특정 동작을 승인했다**고 말하는데, 아무거나 푸는
부여는 그 기록을 추측으로 만든다. 이제 검사한다 — 두 번째를 id 로 지목하기 · **없는 id 는
아무것도 풀지 않기** · id 없이 도구로 되돌아가되 **맞는 도구만** · 아무도 거부당하지 않은
도구는 아무것도 풀지 않기 · id 도 도구도 없는 부여는 아무것도 풀지 않기.

### 아무도 읽지 않는 `isError`

`tool_result` 블록마다 달던 `isError` 를 **읽는 코드가 없다** — 리듀서에 `tool_result` case 가
없고, 두 소비자(`change/explain.js` · `repo.countToolResults`)는 **원본 줄**을 읽는다. 뒤집어도
아무 데서도 아무 일이 없었다.

지웠다. 아무도 읽지 않는 필드는 **아무것도 확인할 수 없는 관측에 대한 주장**이다. 원본 줄에는
그대로 있으니 나중 패키지가 필요하면 거기 있다.

### `scripts` 가 객체가 아닐 때

`(pkg.scripts && typeof pkg.scripts === 'object')` 뒤에 **아무 테스트도 없었다.** 손으로 쓰거나
생성된 `package.json` 은 뭐든 담을 수 있고, `19` §C4 는 빌드 방법을 **지어내지 않는다**고 한다.
문자열 · 숫자 · 불리언 · 배열 · `null` · 키 없음 전부에 대해, 세 규칙이 **던지지 않고**
`no_script` 로 나오는지 잰다.

## 등가 돌연변이 셋 — 그래도 쫓을 값은 있었다

`rules.js` 의 세 `> 1` 은 전부 앞줄이 `=== 1` 로 이미 반환한 뒤라 `>= 1` 과 **구별되지 않는다.**

쫓다가 나온 것: **여섯 규칙이 패턴을 하나도 공유하지 않는다.** 그래서 T1 모호 분기는
**불변식상 도달 불가**다. 주석이 아니라 성질로 못박았다 — 패턴을 공유하는 두 규칙은 한쪽을
영구히 도달 불가로 만드는 **규칙집합의 결함**이지 matcher 가 조용히 풀 일이 아니다. 그리고
실제로 도달하는 쪽(T2b, `실행해줘` → 세 읽기)도 이름을 적어 두었다.

## 곁다리 — 스위트가 멈출 수 있었다

돌연변이 하나가 `await r.done` 을 영원히 기다리게 만들었고 스위트가 그냥 앉아 있었다.
**`node --test` 에는 테스트별 기본 상한이 없다.** 멈춤은 실패가 아니라 **보고하지 않는 CI 작업**
이고, 진단은 "느렸다" 가 된다.

`--test-timeout=60000` 을 붙이고, 그게 붙어 있는지 검사한다. 이 저장소는 읽을 수 없는 방식으로
실패하는 스위트에 이미 한 번 당했다(`tests/tmp.js`) — 교훈은 같다: **실패를 읽을 수 있게 만든다.**

## 허용 카드도 하나 — 스윕 밖에서

`allowSpec` 은 모델의 경로를 **프로젝트 기준으로 해석**한다(상대 `../../../etc/shadow` 가
엉뚱한 트리로 해석된 적이 있어서). 그런데 카드는 **원본 입력**을 보여 주고 있었다. 같은 파일을
두 가지로 적은 것이고, 주석은 "부여가 만들어지는 것이 곧 보이는 것" 이라고 적고 있었다 —
사실이 아니었다.

부여 문자열이 스냅샷과 함께 오고, 카드가 그것을 쓴다. D-133 의 계약은 사람이 **본 것**을
승인하는 것이다.

## 그리고 스윕이 만든 부하가 e2e 를 한 번 흔들었다

워커 넷이 도는 동안 `focusAfterUnderstood` 가 **`BODY`** 로 한 번 나왔다가 다음 실행에서
`intent` 로 돌아왔다. 재현되지 않는 실패는 그냥 넘어가기 쉬운데, **깜빡이는 검사는 없는
검사보다 나쁘다** — 이 런의 모든 "N개 통과" 를 조금씩 덜 참으로 만든다.

주장은 그대로 두고 **기다리는 방식**만 바꿨다: 고정된 800ms 뒤에 한 번 읽는 대신, 최대 120
프레임 동안 폴링해서 포커스가 요청 칸에 **닿는지**를 본다. 닿지 않으면 여전히 실패하고,
그때는 **무엇이 대신 잡고 있었는지**를 보고한다. 상한을 추측이 아니라 결과에 건다.

### 두 번째 흔들림도 같은 모양이었다

두 번째 앱 인스턴스(저장소 거부 부팅)를 확인하는 검사가 `window.__screen is not a function`
으로 죽었다. **앱이 실패한 것처럼 읽히는데 실패가 아니다** — 아직 켜지는 중이었다.

`pageTarget` 은 디버거 타깃을 기다리는데, 그건 **창이 생기는 즉시** 존재한다. 모듈 그래프는
그 뒤에 로드된다. 그 사이를 `await sleep(4000)` 이 메우고 있었고, 4초는 부하가 없을 때의
추측이다.

두 부팅 경로 모두에서 **렌더러가 실제로 로드됐는지**를 기다린다(상한 10초). 로드되지 않으면
여전히 실패하고, 그때는 **그 말로** 실패한다 — "느렸다" 가 아니라 "렌더러가 안 떴다".
