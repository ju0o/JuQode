# 참조 계층 노트 — 코딩 에이전트 작업면의 시각 위계

**작성 근거 (정직하게):** 이 노트는 **새 조사 단계가 아니다** (개정안 §1). 이 모델이 알고 있는
2026-05 시점의 해당 제품 출하 UI 에 대한 지식으로 썼고, **이번에 새로 캡처한 스크린샷은 없다.**
따라서 "측정" 이 아니라 **참조 요약**이다. 시각 스타일은 보지 않았다 — 위계만 봤다 (§1: "The goal
is hierarchy, not imitation").

---

## 1. 세 제품이 공통으로 하는 것

| 질문 | Cursor | Claude Code (CLI) | Codex |
|---|---|---|---|
| 무엇이 시각적 주인공인가 | 코드 편집기 | 하나의 대화 기록 열 | 열려 있는 **하나의 task** |
| 사용자의 요청은 어디 사는가 | 오른쪽 패널 **아래 고정** | 화면 **맨 아래 고정** | task 안 입력칸 |
| 진행 중인 작업은 어디 보이는가 | 그 패널 안에서 위로 흐른다 | 같은 열 안에서 위로 흐른다 | task 본문이 곧 진행 상황 |
| 기록·최근은 어떻게 있는가 | 접힌 목록 / 드롭다운 | 스크롤백 + `/resume` | 왼쪽 **좁은 행 목록** |
| 프로젝트 맥락은 어디 있는가 | 파일 트리(접힘 가능) | **화면에 없다** (물어야 나온다) | 거의 없다 |
| 부차 정보는 언제 나오는가 | 눌렀을 때 | 물었을 때 | task 를 열었을 때 |
| 동시에 경쟁하는 영역 수 | 2 (코드 + 패널) | **1** | 2 (목록 + task) |

## 2. 빌려올 규칙 넷 — 스타일이 아니라 위계

1. **입력칸은 언제나 같은 자리에 있다.** 세 제품 모두 요청 입력 위치가 상태에 따라 움직이지 않는다.
   사용자가 "무엇을 시킬까" 를 고민할 때 눈이 찾아갈 곳이 하나다.
2. **주인공은 하나다.** 나머지는 레일(rail)이거나 접힌 목록이다. 같은 무게의 영역을 여러 개 두지 않는다.
3. **프로젝트 맥락은 상주하지 않는다.** Claude Code 는 아예 안 보여 주고, Cursor 는 접을 수 있고,
   Codex 는 거의 없다. **세 제품 중 어느 것도 프로젝트 설명을 화면의 가장 큰 물체로 두지 않는다.**
4. **목록은 행이지 카드가 아니다.** 기록·최근은 좁고 조용한 행으로 있다가 누를 때 커진다.

## 3. JuQode 가 다르게 해야 하는 것 — 그리고 안 바꿀 것

**다르게:** JuQode 는 비개발자를 위해 **읽어 주는** 제품이므로 위 셋보다 설명이 많다. 그래서 설명을
*언제* 보여 주느냐가 더 중요하다 — 상주시키면 그게 벽이 된다.

**안 바꿀 것:** 카드는 JuQode 의 시각 언어다 (§2: "Cards remain JuQode's visual language").
위 제품들의 밀도 높은 개발자용 목록을 흉내내지 않는다. 확인 칩·정직 문구·Agent Presence 는
JuQode 고유이고 그대로 둔다.
