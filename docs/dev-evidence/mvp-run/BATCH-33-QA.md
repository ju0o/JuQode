## 2. 생존자 35개를 관통하는 패턴은 하나다

**조건이 참일 때는 검사했고, 거짓일 때는 아무도 안 봤다.**

`&&`→`||`, `>`→`>=`, `===`→`!==` 같은 **조건을 넓히는** 변이는 정확히 그 안 본 쪽에서만
드러난다. 패널이 나와야 할 때 나오는지는 전부 검사돼 있었고, **나오지 말아야 할 때 안 나오는지**는
한 곳도 없었다. SC-03 의 다섯 개, SC-04 의 증거 빈틈 두 개, SC-02 의 History 컨트롤이 전부 같은 모양이다.

## 3. 찾은 제품 결함 — 같은 버튼을 세 번 그린다

`실행해줘` 는 `['qc.dev.start','qc.build','qc.test','work']` 로 라우팅된다
(`19` §C4, 목적어 없는 동사). 모호함 카드는 **옵션마다 버튼을 그렸다** — `터미널 열기` 가 세 개,
셋 다 같은 문구로 같은 드로어를 같은 구절로 연다.

카드 자신의 문장은 `어느 쪽인지 골라 주세요. JuQode가 대신 정하지 않아요` 다.
**읽기 세 개를 이름 붙인 게 아니라, 컨트롤 하나를 세 번 그린 것이다.**

두 루프 + `offeredWork` 플래그를 네 줄로 줄였다. Work 는 항상 제공한다 — 라우터는 규칙 두 개가
full 매치하면 `work` 를 아예 빼는데(`19` §C4), 그때 Work 로 가는 길이 없는 카드가 남는다.

**이 수정의 e2e 테스트는 아직 커밋되지 않았다 (§6).**

## 4. e2e 로는 도달할 수 없는 규칙 하나 — 순수 함수로 뺐다

D-126a 의 제외 경로 카드는 조건이 `!gap?.known || !gap.paths?.length` 다. `&&` 로 바꾸면
**빈틈이 없는 Work 에도** `증거에 담기지 않은 변경이 있어요` 가 뜬다.

그런데 이 픽스처가 만드는 **변경이 있는 Work 는 전부** `.env` 도 건드린다. 즉 "빈틈 없는 Work"
라는 상태가 e2e 에 **존재하지 않는다.** `.env` 를 한 번만 쓰도록 고쳐도, 이후 Work 는 `--resume`
이 아니라서 변경 자체를 만들지 않는다.

e2e 를 비트는 대신 판정을 순수 함수로 뺐다 — `killPlan` · `launchArgv` 와 같은 패턴이다.

```js
export function hasEvidenceGap(gap) {
  return Boolean(gap?.known) && (gap.paths?.length ?? 0) > 0;
}
```

`tests/reader.test.js` 가 네 조합을 전부 고정한다. 특히 **`known: false`(대조 자체를 못함)는
카드를 그리지 않는다** — 제외 파일이 안 바뀌었다고 말하는 것도, 바뀌었다고 말하는 것도 둘 다
할 수 없기 때문이다. D-126a 가 막으려는 과잉주장이 정확히 그것이고, 판정 함수는 **경로 개수만**
본다(내용은 열지 않는다).

`return null` → `return {}` 뮤턴트도 같이 죽는다: 반환값이 boolean 이어야 한다는 것을 단언한다.

## 5. 픽스처 하나 추가가 400줄 떨어진 곳을 깼다

Work 두 개짜리 세 번째 프로젝트를 심었더니 최근 목록의 `[1]` 번째 행이 **다른 프로젝트**를
가리키게 됐고, 이후 모든 단계가 엉뚱한 저장소에서 돌다가 **"Agent Presence 캔버스가 없다"**로
터졌다. 증상과 원인이 400줄 떨어져 있었다.

**위치는 정체성이 아니다.** 최근 목록 행 선택을 전부 이름/경로 기준으로 바꾸는 중이다 (§6).
