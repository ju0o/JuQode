| 인수 조건 | 구현 |

| **자동 재읽기 없음** (`19` §C1 ⑤ · D-132) | `juqode:brief` 는 **읽기 전용**이다. 결정론적 스캔만 다시 돌려 `source_hash` 를 비교하고, 모델은 부르지 않고, 아무것도 쓰지 않는다. 바뀌었으면 **말한다** — 다시 읽는 건 `다시 읽기` 버튼뿐이다 |

첫 읽기 실패는 여전히 실패다 — 지킬 것이 없을 때는 `15` 가 요구하는 이유 카드가 맞다.

`source_hash` 는 manifest 와 트리 **모양**만 덮는다(`19` §C1 ⑤). 그래서 README 본문을 고쳐도
Brief 는 늙지 않고, 의존성 하나가 늘거나 최상위 폴더가 생기면 늙는다. e2e 가 둘 다 확인한다.

## 접기 — D-132

첫 열기는 크게, **다시 열기는 접힌 채로**. 접히면 헤더만 남는데, 헤더는 `읽은 시점`을 계속
들고 있다 — 그게 캐시된 Brief 를 캐시된 Brief 로 만드는 사실이다.

오래됨 띠는 접힘 **밖**이다. 접어 둔 사용자에게도 프로젝트가 바뀐 건 말해야 한다.

## 문구에서 나온 것 셋

1. **`18` brief.stale 에 예시 숫자가 박혀 있다** — `3일 전에 읽은 내용이에요.` `19` §C1 ⑤ 는 그
   *형식*(`3일 전 내용` 식)을 요구하므로 승인된 문장을 그대로 두고 **숫자만** 치환한다.
   한국어를 새로 쓰지 않으려고 숫자 문자만 바꾼다. CF-16.
2. **같은 날 바뀐 경우** `0일 전에 읽은 내용이에요` 가 된다. 오래됨은 사실 *나이*가 아니라
   *해시*의 문제라, 읽은 지 몇 분 만에도 바뀔 수 있다. 그 경우는 gap 문구로 사실만 말한다.
3. **`다시 읽기` 가 두 번 그려졌다** — 헤더와 오래됨 띠에. 한 카드 안에 같은 버튼이 둘이면
   사용자가 같은 것을 두 번 고르게 된다. 띠가 떠 있는 동안엔 헤더에서 뺀다.

## 그리고 렌더러가 **없는 문구 키**를 부르고 있었다

새 테스트 하나 — "렌더러가 **이름 부르는** 문구 키가 실제로 있는가" — 가 즉시 셋을 찾았다:

- `C.brief.failTitle` · `C.brief.failNote` — `프로젝트를 읽지 못했어요` 실패 띠가 **제목 없이**
  그려지고 있었다.
- `C.work.done` · `C.work.notDone` — 결과 카드의 `한 것` / `못 한 것` 머리글. **부분 완료
  상태의 핵심인 두 목록 위에 빈 제목 두 개가 그려지고 있었다.**

기존 문구 검사는 *존재하는 문자열*의 출처만 본다. **없는 문자열은 문자열 검사가 볼 수 없다.**
같은 결함이 배치 07 QA 에서도 나왔었다(WBS-19 패널) — 그때는 손으로 찾았고, 이번엔 테스트가
찾는다.
