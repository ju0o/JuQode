## HIGH · **아무도 `watchQuiet` 를 호출해 본 적이 없었다**

푸시 조건의 **어느 부분을 뒤집어도** 스위트가 통과했다:

```js
if (snap.liveness !== 'live' || snap.cancelUnconfirmed) onUpdate(snap);
```

이 함수는 **타이머가 정당한 유일한 자리**다. `15` 가 정의하는 `새 신호 없음` 과
`취소 확인 불가` 는 **신호의 부재**로 정의되고, 그 소식을 전할 이벤트는 그 소식을 거짓으로
만드는 바로 그 이벤트다. 그래서 조건이 틀리면 **아무 오류도 나지 않는다** — 화면이 그 상태들을
그냥 영원히 안 보여 줄 뿐이다.

네 경우를 실제로 몰아서 잰다:

| 상태 | 기대 |
|---|---|
| live | **밀지 않는다** — 소식 없이 타이머로 SC-03 을 다시 그리는 것 |
| quiet | 민다 (침묵 자체가 소식이다) |
| unknown | 민다 |
| live + 취소 확인 불가 | 민다 — 조건의 **다른 절반**, 혼자서 |

마지막 행이 `||` 를 `&&` 로 바꾼 돌연변이를 죽인다. 그리고 첫 행이 `!==` 를 `===` 로 바꾼 것을.

## MEDIUM · 두 git 호출이 어긋났을 때

`zipped.length === names.length ? zipped : blocks.splitDiff(patch)` — `diff` 와
`diff-tree --name-only` 가 **같은 패치를 서술한다는 것**을 확인하는 자리다. 파일 개수가 다르면
**인덱스로 짝지으면 안 된다** — 한 파일의 diff 가 다른 파일 이름 아래로 들어간다.

`splitDiff` 쪽에서 그 어긋남을 직접 잰다: 이름 목록이 맞으면 이름이 이기고(이국적 경로가
제대로 나오는 이유), 짧으면 패치는 여전히 두 파일이라 길이가 갈리고, 이름이 아예 없으면 각
헤더를 읽어 **어느 파일인지**는 언제나 맞다.

감독자 쪽 돌연변이 자체는 **두 git 배관 호출이 실제로 어긋나야** 갈리고, 그 상태를 만드는
픽스처를 만들 수 없다. 남긴다.

### 이 프로그램이 실제로 찾은 것

**제품의 결함 열여섯.** 크기 상한이 어느 트리를 재는지 · 읽을 수 없는 루트가 거부되지 않을 수
있었던 것(두 증거 메커니즘 각각) · 중첩 저장소 원장의 `.git` · `확인됨` 도구 수가 두 가지
이유로 적게 나온 것 · 부분 완료 카드가 목록 하나만 그린 것 · **오프라인 가드를 아무도 호출해
본 적이 없던 것** · 제외 원장이 `.git` 로 걸어 들어갈 수 있던 것 · 읽을 수 없는 파일이 "안
바뀜" 으로 정착될 수 있던 것 · `stop()` 의 SIGKILL 승격이 재활용된 pid 를 칠 수 있던 것 ·
서술 프롬프트가 모델에게 **틀린 사실**을 건넬 수 있던 것 · 실행되지 않은 도구의 결과가 실행의
증거가 될 수 있던 것 · **이름변경 하나가 카드 셋이 되던 것** · 이름이 ` b/` 를 담은 파일 ·
허용 카드가 플래그가 쓰지 않는 문자열을 보여 주던 것 · **`watchQuiet` 를 아무도 호출해 본 적이
없던 것** · 그리고 아무도 읽지 않는 필드/사실 셋(`isError` · `entryHints` · 항등식 map).

**도구의 결함 셋.** 스윕이 죽은 돌연변이를 살아남았다고 신고하던 것(요약 줄 대신 종료 코드) ·
고아 프로세스를 흘리던 것(프로세스 그룹) · `dist` 를 복사해 tmpfs 를 채우던 것.

**스위트의 결함 둘.** 테스트별 상한이 없어 멈출 수 있던 것 · e2e 가 결과를 기다리지 않고 고정
시간 뒤에 한 번 읽던 두 자리.

### 남은 68 — 무엇인가

**Windows 5** (DV-12, 측정할 수 없다) · **등가 또는 도달 불가 63.** 대부분 세 가지 모양이다:

1. **앞줄이 이미 반환한 뒤의 비교** — `=== 1` 다음의 `> 1`, `!before || !after` 다음의 부분 조건
2. **두 경로가 같은 답에 도달** — `path.join(root, '')` 는 `root`, `JSON.parse` 가 대신 던져
   같은 `null`, 헤더 파서와 이름 목록이 같은 경로를 낸다
3. **컴파일러가 만들지 않는 AST 모양** — `isExported` 의 가드는 모듈 수준 `const` 에서 갈리지
   않고, 지역 `const` 는 애초에 방문되지 않는다

`supervisor.js` 의 29 는 대부분 **가드 절의 부분 조건**이다 — `if (!a || !b || !c) return null`
에서 하나를 `&&` 로 바꾸면 *한쪽만* 없는 경로가 필요하고, 그 경로들은 대부분 상위 호출자가 이미
막는다. 값이 있는 셋(위 둘과 `changes.known && files.length === 0`)은 이번에 덮었다.

**결산의 요점은 68 이라는 숫자가 아니라, 그 68 각각에 이유가 붙어 있다는 것이다.**
