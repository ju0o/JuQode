## 먼저: **스윕 도구가 죽은 돌연변이를 살아남았다고 신고하고 있었다**

`while (s !== prev)` 를 뒤집은 돌연변이가 계속 살아남았다. 그런데 손으로 적용해 보니
`normalize('켜줘!ㅋ!')` 가 `켜줘!` 로 나온다 — 내가 그 직전에 쓴 테스트가 잡아야 하는 것이다.

원인: 그 돌연변이는 `tests/interpret.test.js` 를 **멈추게** 만들고, `--test-timeout` 이 그걸
**파일 수준**에서 끊는다. 출력은 이렇게 된다:

```
not ok 1 - tests/interpret.test.js
# tests 1
# pass 0
# fail 0        ← 개별 테스트가 실패한 게 아니라서
```

스윕의 판정이 `'# fail 0' 이 없으면 죽음` 이었다. **요약 줄만 보면 죽은 돌연변이가 살아남은
것으로 읽힌다.** 종료 코드로 바꿨다.

같은 실수가 배치 25 의 `not ok 7 - tests/loop.test.js` 에도 있었다. **검사 도구도 검사가 필요한
물건이다** — 이 런이 제품에 대해 반복해서 말해 온 것과 같다.

(그리고 스윕이 고아 프로세스를 흘리고 있었다: 타임아웃이 부모 `node --test` 만 죽이고 파일별
자식은 남아서, `node tests/qc.test.js` 열두 개가 38분씩 돌고 있었다. 자기 프로세스 그룹으로

## 진짜 구멍

### 서술 층이 모델에게 **틀린 사실**을 건넬 수 있었다

두 가지, 같은 한 문장에서:

- `deterministic.filter((r) => r.confidence === 'confirmed')` 을 뒤집으면 — 사실 층이 **세우지
  못한** 답들이 `## 측정된 사실` 이라는 제목 아래로 간다. `19` §C1: *이 사실만 근거로
  삼으세요.* 확인 못함을 사실로 건네는 것은 **없는 것을 있다고 말하면서** 그 위에 지으라고
  하는 것이다.
- `measured || '(측정된 사실이 없어요)'` 를 `&&` 로 바꾸면 — 사실을 **가지고 있으면서**
  없다고 말한다. 모델은 파일 목록만 보고 답한다.

둘 다 **그럴듯해 보이는 프롬프트**를 만든다. 그래서 다른 어디에서도 드러나지 않았다.

### 실행되지 않은 도구의 결과가 실행의 증거가 될 수 있었다

`b.type === 'tool_result' && runIds.has(b.tool_use_id)` 를 `||` 로 바꾸면 **아무 도구 결과나**
Bash 를 시작만 한 Work 를 만족시킨다.

기존 테스트로는 볼 수 없다 — "편집만 한" 케이스는 Bash use 가 없어서 `runIds` 가 비고 함수가
그 줄에 닿기 전에 반환한다. 필요한 것은 **실행이 시작됐고 다른 것의 결과가 돌아온** 모양이다.
테스트가 도는 동안 모델이 다른 파일을 고치는, 아주 흔한 형태다.

### `외 0개`

`names.length <= 2` 를 `<` 로 바꾸면 파일이 정확히 둘일 때 `a.ts · b.ts 외 0개` 가 된다.
제목은 변경에 대한 **사실**이고, 0을 세는 제목은 아무도 일부러 쓰지 않는 문장이다.

### 인용 기록에 아무 검사도 없었다

`groups.filter((g) => g.confidence === 'confirmed' && g.sourceRef)` — CF-13 때문에 `20` 에
인용을 담을 칸이 없어서 신호로 남기는 그 기록이다. **그 기록이 유일한 인용의 존재처**인데,
잘못된 묶음이 들어가거나 아무것도 안 들어가도 화면의 확인됨은 그대로고 나중에 확인할 방법도
없다.

### 어느 패스가 답했는지

`pass === 'direct'` 가 **두 번** 나오고(동의어를 적용할지, 그리고 tier 라벨) 둘 다 뒤집어도
스위트가 통과했다. 위의 코퍼스는 **route** 만 확인하고 tier 는 실패 메시지에 찍기만 한다.

tier 는 장식이 아니다. `20` 이 실행과 함께 기록하고, `19` §C4 는 동의어 탐지를 **미검증**으로
둔다 — 그래서 어느 패스가 답했는지는 잘못된 추측을 **나중에 추적할** 바로 그 실마리다.

### 꼬리 제거가 한 번만 돌 수 있었다

`do … while (s !== prev)` 가 한 바퀴 만에 나가도 모든 테스트가 통과했다 — 코퍼스의 시끄러운
입력이 전부 한 바퀴에 끝난다(`켜줘!!ㅋㅋ` 은 문장부호 다음 웃음으로 끝). **번갈아 나오는**
꼬리가 루프를 필요로 한다: `켜줘!ㅋ!` 는 부호·웃음·부호라 한 바퀴면 `켜줘!` 가 남고 어떤
규칙에도 안 맞는다.

### 항등식이 규칙인 척하고 있었다

`qc.readings.map((r) => (r === 'work' ? 'work' : r))` — 어느 쪽이든 `r` 이다. 뒤집으면 **모든
읽기가 `work` 가 되고** 아무것도 실패하지 않았다. 아무것도 안 하는 것을 아무도 검사하지 않기
때문이다. 지웠다.

### 그리고 둘 더

`i !== -1 && Array.isArray(answers[i].data?.questions)` 를 `||` 로 바꾸면 목록이 아닌 q6 행에
`.filter` 를 걸어 **던진다** — `merge()` 가 던지면 멀쩡한 Brief 의 서술 패스를 통째로 잃는다
(`19` §C1 ⑥). `!a || typeof a !== 'object'` 를 `&&` 로 바꾸면 `null` 이 걸러지지 않고 `a.q` 에서
던진다 — `[null, {...}]` 은 모델이 항목 하나를 포기했을 때 내놓는 바로 그 모양이다.

## 남은 열둘 — 전부 등가이거나 도달 불가

**JSON 추출 가드 여덟 개**(두 파일 × 넷). `start === -1 || end <= start` 를 `&&` 로 바꾸면
`start` 가 -1 인 경로에서 `JSON.parse` 가 대신 던져 같은 `null` 이 된다. `<=` 를 `<` 로 바꾸는
것은 한 글자가 `[` 이면서 `]` 여야 달라진다. `return null` 을 `return {}` 로 바꾸면 호출부가
`Array.isArray(...) ? ... : []` 이라 똑같이 빈 결과다.

**인용 필터의 `&&`.** 같은 파일 145행이 `sourceRef: confidence === 'confirmed' ? sourceRef : null`
이라, 확인됨이 아닌 묶음은 **언제나** `sourceRef` 가 null 이다. `&&` 와 `||` 가 같은 집합을 낸다.

**예산 경계 둘**(`>` vs `>=`). 정확히 예산과 같을 때 한 줄을 더 생략할 뿐이고, 어느 쪽이든
예산 안이다.

**`for (let i = signals.length - 1; i >= 0; i--)`.** 인덱스 0 이 맞는 `tool_result` 일 수 없다 —
`runIds` 는 그보다 앞선 `TOOL_USE` 에서만 채워진다.
