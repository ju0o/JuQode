## 기록이 실제로 생겼다

SC-02 의 기록 카드는 지금까지 **빈 상태만** 있었다. 그래서 `15` 가 요구하는 `변경 보기` 로
SC-04 에 들어가는 입구가 존재하지 않았고, 끝난 Work 는 화면에 떠 있는 동안에만 닿을 수 있었다.

- `juqode:history` — 이 프로젝트가 시작한 모든 Work, 최신순. 각 행: 사용자의 말(=Work 이름) ·
  outcome 칩 · `변경 n개` · 시각.
- **`변경 n개` 는 측정된 수이거나 아예 표시하지 않는다.** `changes()` 가 `known: false` 를
  돌려주면 `null` 로 실어 나른다 — 0 을 대신 찍으면 아무도 하지 않은 측정을 제품이 주장하는 것이
  된다.
- 행마다 `15` 가 지정한 두 목적지: `결과 보기` → SC-03, `변경 보기` → SC-04. e2e 가 **화면에
  떠 있지 않은 Work** 에 대해 둘 다 실제로 도달하는지 확인한다.
- `18` orient.* 한 문장. **`확인 불가` 는 예약어다** — `21` WBS-20 은 종료되지 않았고 재조정 후
  프로세스를 찾지 못한 Work 에만 허용한다. "아직 안 봤다" 의 대역으로 쓰지 않는다. 끝난 Work 는
  어떻게 끝났든 자기 outcome 을 말한다.
- 리스트가 채워지기 전에는 아무것도 그리지 않는다. `아직 끝난 작업이 없어요` 는 이 프로젝트에
  대한 **주장**이고, 알기 전에 하지 않는다.

## 시각 QA 에서 나온 레이아웃 결함, 그리고 그걸 못 잡던 검사

기록에 행이 생기자마자 **기록 카드가 Brief 위에 겹쳐 그려졌다.**

`17` 의 "모듈 보드 · 6열 격자" 를 6열 그리드 + `grid-auto-flow: dense` + auto row 로 구현했는데,
측정해 보니 **591 px 짜리 카드를 449 px 짜리 행에 담고**, dense flow 가 Brief 이 이미 칠하고 있는
자리에 다음 카드를 밀어 넣었다. `align-self: stretch` 로 바꾸면 실패가 옮겨갈 뿐이다 — 카드가
정확히 두 행에서 **자기 내용을 잘랐고**, 그건 `16` §4 가 금지한다.

**두 개의 컬럼 스택**으로 바꿨다. 스택은 겹칠 수 없다. 카드는 내용만큼 높고 다음 카드는 그
아래에서 시작한다 — 틀릴 행 산술이 없다.

그리고 기존 겹침 검사는 **`.sc03 .card, .sc02 .card` 를 SC-03 에 있는 동안** 돌고 있었다.
`.sc02 .card` 쪽은 항상 0개를 셌고, 그래서 절대 실패할 수 없었다 — 이 런에서 반복해 나오는
그 모양이다. SC-02 위에서 도는 겹침·클리핑 검사를 따로 뒀고, 카드 수가 3개 미만이면 그
검사 자체가 실패한다.

## 남은 것

- `접기`(`18` history.collapse) 와 `n개 더`(history.more) — `15` 의 레이어 카드 4장 + 개수 표현은
  아직 없다. 지금은 전부 나열한다.
- 재진입 orientation 의 `확인 불가` 경로는 WBS-34 가 `ended_unknown` 을 쓰기 시작해야 화면에서
  볼 수 있다. 규칙은 구현돼 있고 e2e 로는 아직 못 만든다.
