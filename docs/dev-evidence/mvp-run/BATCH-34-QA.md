# Batch 34 — 막혀 있던 빨간 단언 하나, 그리고 DV-11 GO

배치 33 은 **미완으로** 커밋됐다. e2e 단언 약 10개가 stash 에 있었고, 그 상태에서 스위트가
빨간불이었기 때문이다. 이 배치는 그것을 풀고, 스윕이 남긴 생존자에 손을 대고, PM 판정을 받아
`15` TD-01 의 Primary Action 을 구현하기 시작한다.

## 1. 빨간 단언의 진짜 원인 — 세 번의 추측이 전부 틀렸다

실패하던 단언: `the drawer did not reopen in the second project`.

배치 33 의 기록은 원인을 **"내가 바꾼 프로젝트 전환 행 선택"** 으로 적어 두었고, 세 번 고쳐
봤지만 전부 실패했다. 그 셋이 전부 추측이었다.

이번에는 값을 먼저 찍었다 (`tmp-visual/results.json`, 이제 매 실행이 남긴다):

| | 값 |
|---|---|
| `beforeSwitch` | `/tmp/juqode-seed2-R8MXcE` |
| `switchedTo` | `/tmp/juqode-seed-Pe0kHx` ← **전환은 정확했다** |
| `drawerAfterSwitch` | `{open:false, card:null, phrase:"", run:null}` |

**행 선택은 처음부터 문제가 아니었다.** 원인은 단언 자체였다:

- `nav.toPicker()` 가 `clearDrawerState()` 를 부르고, 그 함수가 `drawerOpen = false` 로
  닫는다. **드로어는 프로젝트와 함께 닫힌다** — 프로젝트가 없는 SC-01 위에 열린 드로어는
  cwd 가 없어 모든 컨트롤이 null 프로젝트에서 실패한다. 그게 제품 규칙이다.
- 통과하던 옛 버전은 읽기 **직전에** `__toggleDrawer()` 로 다시 열어 `open === true` 를
  만들고 있었다. 배치 33 작업이 그 줄을 지웠고, 단언만 남았다.

그래서 단언을 제품 규칙대로 뒤집었다: 전환 후 드로어는 **닫혀 있고**, 카드 · 구절 · 실행
결과는 전부 비어 있다. 후자가 배치 12 HIGH(카드가 프로젝트를 건너간다)를 지키는 절반이다.

**교훈은 배치 33 이 이미 적어 둔 것과 같다** — 관찰 지점과 단언 사이에 손을 대면 그 테스트가
보려던 상태가 사라진다. 다른 점은 이번에는 **찍어 보고** 알았다는 것뿐이다. 세 번의 추측보다
한 번의 `results.json` 이 쌌다.

## 2. td01 생존자 9개 — 픽스처가 그 상태를 만들 수 없었다

살아남은 이유는 하나였다: **픽스처의 `dev` 스크립트가 `vite` 인데 설치돼 있지 않아 뜨자마자
죽는다.** 돌고 있는 개발 서버가 이 런에 존재한 적이 없으니, 이미 돌고 있는 것도 없고 꺼야 할
것도 없었다.

`dev` 를 계속 살아 있는 프로세스로 바꾸고 `build: 'vite build'` 는 그대로 뒀다 — 실패 상태는
그것이 만든다. 두 종류의 끝이 다 필요했다. 이제 실제로 그려지고 단언되는 것:

| 상태 | 실측 |
|---|---|
| 계속 실행 중 | `멈추기` · `켜 둔 채로 다음 요청`, 빨강 0 |
| 이미 켜져 있음 | `지금 안 됨 · 실패 아님` + 이유 + `pid 10759` |
| 실패 | 종료 코드 **127** · `sh: 1: vite: not found` · `▸ 다시 실행` **그리고** `▸ Claude Code 작업으로 요청` · 빨강 1 |
| 고정 동작 둘 | 터미널 열기의 cwd 문장 · 정지의 pid + SIGTERM/SIGKILL 문장 |
| 멈춤 | `멈췄어요` 로 끝나고 `끝났어요` 라고 하지 않는다 (`07` §8.1) |

그리고 이 런이 켠 서버가 정말 죽었는지 **저장소에 되묻는다** — 테스트가 프로세스를 남기면
다음 실행이 엉뚱한 이유로 실패한다(배치 31 의 교훈).

**한 번 틀렸다:** `멈춤 요청함` 을 700ms 뒤에 관찰하려 했는데 이미 `멈췄어요` 였다. 이
픽스처의 서버는 SIGTERM 에 즉사한다. 고정 지연으로 전이 상태를 잡으려 한 것이 틀렸고, 두
상태 중 하나임을 단언하고 **거짓이 되는 상태**(끝났어요 · 실행 중)가 아님을 단언하는 것으로
바꿨다. 관찰할 수 없는 것을 관찰했다고 하지 않는다.

## 3. 스윕 재측정 — 처음으로 "몇 개가 실제로 죽었는지" 를 쟀다

배치 33 은 생존자 35개를 남기고 **재측정하지 않았다** — 테스트가 커밋되지 않았으니 잴 대상이
없었다. 이번에 그 35개만 다시 돌렸다(`ONLY=<이전 results.json>`). 사이트는 인덱스가 아니라
자기 자신(파일 · 연산자 · 주변 코드)으로 맞춘다: 파일이 그 사이 바뀌었고, **인덱스로 맞추면
엉뚱한 자리를 재고도 잰 줄 안다.**

| | 개수 |
|---|---|
| 배치 33 이 기록한 생존자 | 35 |
| 코드가 **사라진** 것 (GONE) | 6 |
| 다시 돌린 것 | 29 |
| **새 테스트가 죽인 것** | **13** |
| 아직 살아 있는 것 | 16 |

사라진 6개는 배치 33 이 그 코드를 다시 썼기 때문이다 — sc02 의 중복 버튼 루프 4개(두 루프가
네 줄이 됐다), sc04 의 증거 빈틈 조건 2개(`hasEvidenceGap` 순수 함수로 빠졌다). 죽은 것으로
세지 않고 GONE 으로 보고한다. **없어진 코드는 죽인 것이 아니다.**

현재 트리 기준으로 다시 세면: 사이트 62개 중 46개 사망 — **kill rate 74%** (배치 33 시점 49%).

### 아직 살아 있는 16개 — 다음 배치의 재료

| 파일 | 개수 |
|---|---|
| `td01.js` | 5 |
| `sc02.js` | 4 |
| `sc04.js` | 4 |
| `sc03.js` | 3 |

td01 다섯 개 중 넷은 **아직 화면에서 안 해 본 경로**다 — 배치 33 과 같은 모양이고, 이번에
도달한 상태들과는 다른 경로다:

- 모호함 카드에서 **읽기를 고르는** 경로 (`id === 'work'` · `x.id === id`) — 카드가 그려지는
  것은 검사했지만 **버튼을 눌러 본 적이 없다.**
- 실행 중 카드의 **멈추기 버튼** 경로 (`x.id === 'qc.dev.stop'`) — 이번 배치는 `서버 꺼줘` 로
  라우팅해서 껐고, 버튼은 안 눌렀다.
- 실패 카드 재실행 버튼의 강조 클래스 (`r.state === 'failed' ? ' rec' : ''`).

다섯 번째(`r.reason === 'already_running' && r.data?.pid` → `||`)는 **동등 뮤턴트로 보인다**:
그 자리는 `!r.available` 안이고 pid 는 already_running 일 때만 실려 온다. 관찰 가능한 차이를
아직 못 찾았고, 못 찾았다고 적는다 — 죽이지 못한 것을 죽였다고 하지 않는다.

## 4. DV-11 판정 — 파이프 셸 GO

PM 판정 (2026-09-10): **파이프 셸**, `DV-11-DECISION.md` §4 의 동반 조건 네 개 전부 승인.

조건 네 개는 후속 과제가 아니라 구현의 일부다:

1. 한계를 화면에서 말한다 (`sudo`/`ssh`/자격증명은 **묻지도 못하고** 끝난다)
2. 그 실패를 빨강으로 그리지 않는다 — 능력 한계는 실패가 아니다
3. 색 없음과 순서 근사도 고지한다
4. 줄 사이 셸 상태를 유지한다 — 장수 셸 하나

### 무엇이 들어갔나 (메인 프로세스)

`app/main/term/session.js` — **제품에서 셸이 있는 유일한 자리**이고, 사용자가 친 문자열이
셸에 닿는 유일한 경로다. 능력 격리 검사의 `child_process`/`spawn(` 소유자 목록에 다섯 번째
파일로 명시했다 — "어디서 셸에 닿나" 를 한 곳에서 답할 수 있게.

- 셸은 **하나**, 줄이 stdin 으로 흘러간다 (조건 ④). 스파이크가 `cd` 를 `LOST` 로 잰 것은
  줄마다 새 셸일 때다.
- 종료 코드는 난수 마커 + `printf` 로 받는다. **천장:** 명령이 마커를 스스로 출력하면 끝난
  것으로 읽는다. 막을 방법은 별도 파일 서술자뿐이고 셸마다 다르다 — 안고 가되 숨기지 않는다.
- POSIX 셸만 쓴다(아니면 `/bin/sh`). fish 는 `$?` 가 없어 마커가 **조용히** 깨진다 —
  사용자에게는 명령이 영영 안 끝나는 것으로 보인다. 어느 셸인지는 화면이 말한다.
- `limits` 로 한계를 **사실로** 내보낸다. 화면 문장은 지어낸 것이 아니라 이 값과 일대일이다.
- `stop()` 은 **세션을 끝낸다.** 작업 제어가 없어 명령 하나만 끊을 수 없다.

**필터는 없다. 없는 것이 계약이다** (`19` §C4). `tests/term.test.js` 가 차단 목록이 생기지
않는 것을 검사한다 — 걸러내는 척하는 제품은 걸러내지 못한 것을 안전하다고 가르친다.

### 코드를 다시 읽다가 나온 결함 둘

- **끝난 줄이 자기 이름을 잃었다.** 마지막 업데이트는 `running` 을 비운 뒤에 나가는데 줄
  이름을 거기서 읽고 있었다. 카드가 **읽을 것이 생긴 바로 그 순간** `$ …` 머리를 잃는다.
- **stderr 가 사라졌다.** 실측: `echo out; echo err 1>&2` 가 `out` 만 보였다. 마커는 stdout
  으로 오고 stderr 는 아직 오는 중이다 — 코드를 받자마자 줄을 끝내면 stderr 가 다음 줄의
  칸으로 밀리거나 없어진다. `qc/run.js` 가 자식 exit 뒤에 두는 것과 같은 유예를 뒀다.
- **프로젝트가 바뀌면 종료 — 다음에 열 때가 아니라 바뀔 때.** 셸을 여는 순간에만 검사하면
  사용자가 떠난 프로젝트의 디렉터리에서 셸이 계속 돌고, 화면에는 끌 방법이 없다.

## 5. 아직 아닌 것 — 이 배치의 정직한 경계

- **Windows 는 여전히 아무것도 재지 않았다.** 파이프 셸도 ConPTY 도. DV-11 GO 는 Linux 실측
  위에서 내려졌고, `shellFor()` 의 Windows 갈래는 **측정이 아니라 자리표시**다 —
  `$?`/`printf` 마커는 cmd.exe 에서 그대로 돌지 않는다. DV-13/14/15/16 은 사용자 재실행 대기.
- **`15` TD-01 의 지금 안 됨 상태(셸이 시작되지 않음)는 그렸지만 도달해 본 적이 없다.**
  이 픽스처는 셸 시작 실패를 만들 수 없다. 카드는 있고, 렌더된 증거는 없다 — 그렇게 적는다.
- **동반 조건 ② 는 부분적으로만 확인됐다.** 능력 한계를 빨강으로 그리지 않는다는 규칙 중
  이 런이 도달할 수 있는 상태가 위의 미도달 카드뿐이다. 실패한 명령(종료 코드 ≠ 0)이
  빨강인 것은 확인했고, 그것은 **사용자 명령의 실패**이지 능력 한계가 아니다.
- **마커 천장.** 명령이 마커 문자열을 스스로 출력하면 줄이 끝난 것으로 읽힌다. 난수로 추측을
  막았을 뿐 원리적으로 막지 못한다. 별도 파일 서술자가 답이지만 셸마다 다르다.
