# DV-11 판정 재료 — TTY 없는 파이프 셸을 실측했다

**이 문서는 결정을 내리지 않는다.** `21` WBS-00 이 만들라고 한 것 — 판정 재료 — 을 만든다.
DV-11 의 세 선택지 중 **네이티브 모듈이 필요 없는 하나**(파이프 셸)가 실제로 무엇을 하는지
재서, 제품 결정이 직관 대신 숫자 위에서 내려지게 한다.

- 스크립트: `scripts/spikes/pipe-shell.mjs` (일회용 임시 디렉터리, 실제 프로젝트를 건드리지 않음)
- 측정 환경: **linux 7.0.0-31-generic · node v22.22.1** — **Windows 는 여전히
  DEFERRED_VALIDATION 이고 이 문서는 Windows 에 대해 아무 말도 하지 않는다**
- `19` §C6 REC-010 이 스스로 적어 둔 것: *"Real T1 must validate: pty libraries per runtime;
  Windows ConPTY"*

## 측정값

| 무엇 | 관측 |
|---|---|
| `isatty` | **NOT_A_TTY** |
| 색 (`ls --color=auto`) | 이스케이프 없음 — 평문 |
| stdin 으로 질문에 답하기 | `name? got:juqode` (종료 0) — **된다** |
| stdin 이 닫혀 있을 때의 질문 | `name? got:[]` (종료 0) — **멈추지 않는다, 빈 답을 받는다** |
| 전체화면 프로그램 | `top -b -n 1` 은 된다 (배치 모드가 있는 것만) |
| 작업 제어 | `set -m` 은 **받아들여진다**; **제어 터미널 없음** |
| `/dev/tty` 직접 접근 | **NO_DEV_TTY** |
| 그룹 시그널로 정지 | `signal=SIGTERM` — 된다 |
| 줄 사이 상태 (`cd`) | **LOST** (줄마다 새 셸이면) |
| stdout/stderr 순서 | 두 파이프로 분리 — 실제 순서로 합쳐지지 않는다 |

## 이 숫자들이 결정에 무엇을 말하는가

### 결정적인 것 하나 — `NO_DEV_TTY`

`sudo` · `ssh` · git 자격증명 프롬프트는 **stdin 을 읽지 않는다.** `/dev/tty` 를 열어서 터미널에
직접 말한다. 제어 터미널이 없으면 그 경로가 없다.

**즉 그런 명령은 "물어보지 못한 채 실패한다."** 사용자에게는 명령이 그냥 안 된 것으로 보인다.
이것은 품질 저하가 아니라 **그 용도로는 쓸 수 없다**는 뜻이고, 파이프 셸을 고른다면 제품이
그 사실을 **화면에서 말해야 한다** — 원칙 2(숨기지 않는다).

### 멈추지 않는다, 틀린 답을 받는다

닫힌 stdin 은 EOF 다. `read` 가 **빈 값으로 즉시 성공한다.** 사용자가 볼 수 있는 정지가 아니라
**조용히 전달된 틀린 답**이다. 이쪽이 더 나쁘다 — 화면에 아무 이상이 없다.

### 저평가하지 말아야 할 것 — 되는 것도 많다

- **정지는 이미 해결돼 있다.** 그룹 시그널이 듣는다. WBS-23 이 쓰는 바로 그 메커니즘이고
  이미 실측돼 있다.
- **stdin 을 파이프로 넣으면 대화형 프로그램에 답할 수 있다.** 드로어가 입력 줄을 stdin 으로
  연결하면 `read` 를 쓰는 프로그램은 동작한다.
- 배치 모드가 있는 프로그램은 돈다.

### 셸 하나인가 줄마다 하나인가

`cd` 가 다음 줄로 이어지지 않았다. 줄마다 새 프로세스를 띄우면 **세션이 아니다** — 사용자가
`cd` 를 치고 다음 줄에서 다른 곳에 있게 된다. 하나를 살려 두면 그 수명·정리·재조정이
따라오고, 그건 WBS-34 가 Work 프로세스에 대해 이미 하는 일과 같은 종류의 일이다.

### 색과 순서는 진짜 손실이지만 실패는 아니다

색이 없고, stdout/stderr 가 두 파이프라 실제 순서로 합쳐지지 않는다. 빌드 로그를 읽을 때
체감된다. `19` §C4 는 stderr 를 숨기지도 분리하지도 않는다고 말하는데, 파이프 둘로는 **분리를
피할 수 없다** — 합치는 순서가 근사치가 된다.

## 세 선택지, 실측 뒤

| | 무엇을 얻나 | 무엇을 잃나 | 이 런에서 검증 가능한가 |
|---|---|---|---|
| **node-pty** | 진짜 터미널 — `/dev/tty` · 색 · 순서 · 작업 제어 | 네이티브 모듈(Electron 버전마다 재빌드) · 이 저장소의 능력 격리 검사가 금지 · Windows ConPTY 미검증 | **아니오** |
| **파이프 셸** | 네이티브 모듈 없음 · 정지는 이미 됨 · stdin 으로 답 가능 | `sudo`/`ssh`/자격증명 **불가** · 색 없음 · 순서 근사 · 세션 상태를 직접 관리 | **예 (Linux). Windows 는 여전히 미검증** |
| **mock** (`18` `term.mock`) | 아무것도 실행하지 않으니 아무것도 틀리지 않는다 · 문구가 이미 있다 | 셸 줄이 없다 — `15` TD-01 의 요구가 남는다 | 예 |

## 아직 재지 않은 것

- **Windows.** ConPTY 도, Windows 의 파이프 셸도 재지 않았다. 이 문서의 어떤 줄도 Windows 에
  적용된다고 말하지 않는다.
- **Electron 안에서.** 이 스크립트는 순수 Node 에서 돌았다. Electron 의 메인 프로세스에서
  같은 결과가 나오는지는 별개의 측정이다(같을 가능성이 높지만, 높다는 것은 측정이 아니다).
- **node-pty 를 실제로 들여 본 것.** 능력 격리 검사가 금지하고 있어서 시도하지 않았다.

## 결정은 여전히 열려 있다

DV-11 은 제품 결정이다. 이 문서는 그 결정의 **비용을 구체적으로** 만들었을 뿐이다:
파이프 셸을 고르면 `sudo`/`ssh`/자격증명 프롬프트가 **물어보지도 못하고 실패한다**는 것을
제품이 화면에서 말해야 한다.
