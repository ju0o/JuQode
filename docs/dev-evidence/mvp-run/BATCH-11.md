## 인수 조건을 어떻게 읽었는가

`21` 은 `visual regression against the VD frames` 라고 적어 두었다. VD 프레임은 디자인
산출물이고 앱의 렌더 결과와 픽셀로 비교하면 **정당한 차이에서도 실패한다** — 폰트 힌팅,
플랫폼 렌더러, 실제 데이터. 그래서 픽셀 비교 대신 **`16` §2.1 이 실제로 요구하는 성질**을
브라우저에서 측정한다. 픽셀 비교보다 강한 검사다: 무엇이 왜 틀렸는지 말한다.

여섯 상태(`확인됨 · 부분 · 대기 · 실패 · 알 수 없음 · 사용 불가`)를 실제 칩으로 그려 놓고,
**라이트/다크 두 테마 모두에서** 계산된 스타일을 잰다. 테마 블록 하나에만 재정의된 토큰은
이 저장소가 이미 한 번 출시한 적 있는 실패다.

| 검사 | 근거 |
|---|---|
| 모든 쌍이 **색**으로 구별된다 | `16` §2.1 |
| 모든 쌍이 **색이 아닌 것**으로도 구별된다 | `16`: 표식이 흑백 인쇄와 색각 이상 독자에게 남는 것 |
| 부분(채움)과 대기(윤곽)의 **배경이 다르다** | `16` §2.1 이 이 쌍을 콕 집어 말한다 |
| 붉은색은 하나뿐 — 실패만 | `16` §2 |
| 알 수 없음만 dashed, 나머지는 아니다 | `16` §2.1 "dashed blue-grey" |
| 모든 상태가 표식을 가진다 | 위와 같음 |

## 측정이 찾은 것

**실패와 사용 불가가 색으로만 구별되고 있었다.** 둘 다 표식이 없었다. 라이트 테마에서 배경
휘도가 244 와 241 — 흑백으로 인쇄하면 같은 칩이다.

이건 `12` §16 이 제품 약속으로 못 박은 바로 그 쌍이다: **사용 불가 ≠ 실패.** 지금 화면에서
둘을 갈라 주는 건 글자뿐이었다(`지금 안 됨 · 실패 아님`). 문법 자체가 갈라 주지 않았다.

표식을 붙였다 — 실패 `×`, 사용 불가 `○`. 나머지 넷은 이미 있었다(`✓ ◧ ◔ ?`).

`알 수 없음 → solid` 이 살아남았다. `?` 표식이 남아 있어서 "쌍끼리 구별된다" 는 여전히 참이기
때문이다 — 그런데 **dashed 는 Canon 이 직접 적어 둔 것**이다. "서로 다르다" 만 검사하면 Canon 이
지정한 *모양*을 잃는 것을 못 본다. `16` §2.1 이 이름 붙인 모양들을 직접 단언하는 검사를 추가하니
죽었다. **5/5 killed.**
