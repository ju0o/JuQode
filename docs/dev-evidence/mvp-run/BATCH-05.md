## WBS-18 · the result, and what each part of it is worth

D-114's vocabulary is a rule about EVIDENCE, so the code is organised around where each claim
comes from rather than around how it reads:

| | |
|---|---|
| **확인됨** | a deterministic fact backs it — a file the evidence pair measured as changed, or a tool result JuQode itself observed. It carries the source it rests on, and a test fails if a confirmed claim has none. |
| **예상됨** | Claude Code reported it and nothing measured it. Its own words are carried, not paraphrased into JuQode's voice. |
| **확인 못함** | nobody established it either way. A basis that could not be compared is this — never "nothing changed". |

Each claim gets its OWN chip on screen. A single chip over a mixed list would assert one
confidence for several different things, which is the decoupling D-114 exists to prevent — and
which this run shipped once already, in batch 04, where the result chip always read 확인됨.

A 부분 result carries **both** lists (`21` WBS-18): 된 것 from the measured file list, 안 된 것
from refusals the user never resolved. `verify()` fails a partial result that has only one.

Nothing here reads an exit code. `07` §8.1 measured that a cancelled child exits 0, and a run
whose tool was denied reports success — so every judgement comes from signals and the evidence
pair.

## WBS-27 · Code Blocks

D-127: a block is **the innermost NAMED declaration containing a changed line**. Several hunks
inside one declaration become one block; a change outside every declaration is a hunk block and
does not vanish.

- **S1** for TS/JS/TSX/JSX/MJS/CJS — real declarations from the TypeScript compiler API, both
  sides parsed. If **either** side reports parse diagnostics the whole file falls back to S2: a
  block built half from a trusted parse and half from an untrusted one is a unit nobody can check.
- **S2** for everything else — hunk blocks, marked `unblocked` for the structured formats where
  단위로 나누지 못함 is the honest answer and Raw is how to read it.
- Binary → `undisplayable`; over 1 MiB → `too-large`, Raw only.

A **rename** is claimed only when it is derivable (A-14): same file, identical body once the
name token is removed, same `SyntaxKind`, and the old name absent from the other side. If the
body moved too it is a delete plus an add, because calling that a rename would be a guess.

The diff is generated by the app at a fixed `-U3`, since D-127 notes that S2 block identity
depends on the context width — it cannot be left to whoever produced the patch.

`19` §C5-B is explicit that an LLM may EXPLAIN a block and must never DEFINE one. A test fails
if the segmenter reaches for a session, a spawn or a fetch at all.

### Two bugs found while building it

- **Before- and after-side line numbers were pooled into one list**, so a block reported lines
  that do not both exist in any single version of the file. They are kept apart now.
- **A hunk block was emitted per hunk whenever any line fell outside a declaration**, duplicating
  lines a declaration had already claimed. Only the outside lines become hunk blocks.

Both were caught by a fixture that produced a real `git diff -U3` rather than a hand-built
whole-file hunk — the first fixture marked every line as changed, so an untouched sibling
declaration looked touched.

### One found in the result pipeline

The live entry was released the moment a Work's status became `ended` — before the result was
built from it. `entryFor` then rebuilt a bare state from the row, and **Claude Code's own report
vanished from the result it belongs to**. The entry is released after the result is written now.
