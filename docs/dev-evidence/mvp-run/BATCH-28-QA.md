## HIGH · 이름변경 하나가 카드 셋이 되고 있었다

돌연변이를 쫓다가 나왔다. 여러 선언이 있는 파일에서 이름변경 검출을 확인하려고 테스트를
쓰는데, **손대지 않은 선언이 변경으로 보고되지 않는지**도 함께 재려다 실제 동작을 봤다:

```
newName 추가 · oldName 삭제 · newName 이름변경
```

**한 번의 수정이 블록 셋이다.** `renames()` 가 자기가 도출된 블록들 **위에 이어 붙여지고**
있었다. 읽는 사람에게는 세 가지 일이 일어난 것으로 보이고, `19` §C5-B 는 단위를 **하나**로
센다. 추가/삭제 쌍은 이름변경의 **추가 증거가 아니라 같은 사실**이다 — 이해되기 전의 형태일 뿐.

이제 이름변경이 자기가 도출된 쌍을 **대체한다**. 양쪽 줄 번호를 다 들고 있으므로 쌍이 알던 것은
아무것도 잃지 않는다.

**그리고 삭제 하나가 둘로 이름변경될 수 있었다.** 중첩 루프에 break 도 표시도 없어서, 같은 본문을
가진 추가 둘이 같은 삭제를 각각 주장했다 — 카드가 **같은 삭제가 서로 다른 두 함수가 됐다**고
말한다. 한 삭제는 한 번만 주장된다.

## HIGH · 이름이 ` b/` 를 담은 파일

`headerPath` 의 **반반 산술** 분기는 `lastIndexOf(' b/')` 가 경로를 틀리게 읽기 **때문에**
있는데, 자기 테스트가 없었다.

`diff --git a/x b/y.ts b/x b/y.ts` 는 이름이 `x b/y.ts` 인 **파일 하나**다. 마지막 ` b/` 로 읽으면
`y.ts` 가 되고, 카드는 **존재하지 않는 파일에 변경을 귀속시키고** 실제로 바뀐 파일은 언급되지
않는다. 같은 길이의 이름변경(`a/aaa.ts b/bbb.ts`)과 C-인용된 한글 경로도 함께 잰다.

## MEDIUM · 아무도 읽지 않는 스캔 사실

`entry: typeof j.main === 'string' ? j.main : null` 을 뒤집어도 아무 데서도 아무 일이 없었다 —
`facts.entryHints` 가 수집되고 **제품의 어느 줄도 읽지 않았다.**

아무도 읽지 않는 사실은 **아무도 확인할 수 없는 주장**이고, 매니페스트마다 스캔 비용이 든다.
지웠다. 그리고 다시 생기지 않도록, **스캔이 모으는 키 전체를 열거해서** 각각을 답 층이나 서술
프롬프트가 실제로 읽는지 검사한다. 새 키는 여기서 정당화되어야 한다.

(`readme` 는 서술 프롬프트로만 간다 — 그건 leftover 가 아니라 쓰임이다.)

## 남은 열다섯 — 왜 남는가

**등가:**

- `headerPath` 의 두 `&&` — 어느 절이 참이든 대체 경로(`lastIndexOf(' b/')`)가 **같은 답**을
  낸다. 둘이 갈리는 입력을 만들려면 이름변경의 두 이름이 길이가 같으면서 뒤쪽 이름이 다시
  ` b/` 를 담아야 한다.
- `innermost` 의 `(d.end - d.start) < (best.end - best.start)` → `<=` — 같은 줄을 담으면서
  길이가 같은 선언 둘은 같은 선언이다.
- `innermost` 의 `return null` → `return {}` — 호출부가 `if (d)` 로 받고 `{}` 는 참이지만
  이어지는 `touch(d, …)` 가 `d.name` 을 `undefined` 로 읽어 같은 hunk 블록으로 떨어진다.
- 예산 경계 `size > MAX_DISPLAY_BYTES` → `>=` — 정확히 상한일 때 한 파일이 더 S2 로 갈 뿐이고,
  어느 쪽이든 상한 안이다.

**도달 불가:**

- `isExported` 의 두 돌연변이 — 모듈 수준 `const` 의 부모 사슬은 **언제나** `VariableStatement`
  라 그 가드가 갈리지 않고, 함수 내부의 지역 `const` 는 애초에 `declaredName` 이 방문하지
  않는다. 갈리는 것은 `for (const x of …)` 같은 모양뿐이다.
- `after === null && before === null` 계열 — 한쪽만 null 인 경로는 바로 위 줄이 이미 반환한다.
- `renames` 의 `!before || !after` → `&&` — 두 소스가 다 없을 때만 다르고, 그 경우 위쪽에서
  이미 S2 로 빠진다.
- 식별자 토큰 치환의 `T.isIdentifier(n) && n.text === name` → `||` — 이름이 없는 블록은
  `bodyText` 를 부르지 않고, 이름이 있으면 그 이름의 토큰만 후보다.
- `scan.js` 의 `kind === null` — dirent 가 파일도 디렉터리도 심볼릭 링크도 아닌 경우로만
  갈리고, 그 경우 `lstat` 폴백이 같은 답을 낸다.

이 파일은 **AST 형태에 걸린 분기가 많고**, 그중 상당수는 TypeScript 컴파일러가 실제로 만드는
트리에서 도달할 수 없다. 각각의 이유를 숫자가 아니라 문장으로 남긴다.
