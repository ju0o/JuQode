없다. 단언을 그것으로 바꿨다.

## 2. 다섯 번째는 동등 뮤턴트가 아니었다

배치 34 는 `r.reason === 'already_running' && r.data?.pid` → `||` 를 **동등해 보인다**고 적고
"관찰 가능한 차이를 못 찾았다" 고 남겼다. 찾았다.

카드는 **스냅샷**이고, 확인 시점에 `ipc.js` 가 availability 를 다시 묻는다. 거절되면
렌더러는 `{...r, available: false, reason: started.detail}` 로 바꾸는데 — **`data` 는 설명
시점의 것이 그대로 남는다.** 정지 카드의 data 에는 pid 가 있다.

그래서 설명과 확인 **사이에 서버가 죽으면**:

| | `&&` (지금) | `||` (뮤턴트) |
|---|---|---|
| 거절 카드 | `지금 안 됨 · 실패 아님` + `JuQode 가 켠 개발 서버가 지금 없어요` | 같은 문장 **+ `pid 129778`** |

즉 뮤턴트는 **"그 서버는 지금 없어요" 라고 말하면서 그 서버의 pid 를 함께 보여 준다.**

e2e 가 그 경로를 실제로 만든다: 서버를 켜고 → 정지 카드를 띄우고 → **앱 밖에서** 그 pid 를
죽이고(크래시가 하는 그대로) → 앱이 알아챌 때까지 기다린 뒤 → 낡은 카드의 `실행` 을 누른다.
실측:

```
BEFORE: … JuQode 가 켠 개발 서버 프로세스(pid 129778, npm run dev)에 종료 신호(SIGTERM)를 …
AFTER : 지금 안 됨 · 실패 아님 | JuQode 가 켠 개발 서버가 지금 없어요. …   ← pid 없음
```

**덤으로 얻은 것:** `19` §C4 의 "설명과 확인은 두 번의 왕복" 과 `ipc.js` 의 "카드를 믿지 않고
확인 시점에 다시 묻는다" 가 이제 검사된다. 그 경로에는 검사가 하나도 없었다.
