## 그린 것

### `15` SC-01 · UF-RETURN — 최근 프로젝트 행의 마지막 작업

`15` SC-01 과 `22` §B 2행이 요구한다: 최근 목록의 각 행이 **마지막 Work 를 요약**한다 —
사용자가 적은 그대로의 요청과 결과 칩.

`recentProjects` 가 프로젝트당 가장 최근 Work 하나를 left join 한다. 조건 둘:

- **`started_at` 기준으로 마지막.** 아직 도는 Work 가 마지막이고, 그게 돌아온 사용자가 봐야
  할 것이다
- **진행 중은 결과가 아니다.** 끝나지 않은 Work 는 대기 칩을 받지 다섯 종결 제목 중 하나를
  받지 않는다
- Work 가 없는 프로젝트는 `null` — 화면이 아무것도 안 그린다. **빈 요약은 아무 말도 안 하면서
  자리만 차지한다**

SC-01 의 기존 스크린샷은 **Work 가 생기기 전에** 찍혀서 이 상태를 담을 수 없다.
`sc01-return-{light,dark}.png` 를 따로 찍는다.

### `15` SC-03 Remaining-unknown — 남은 변경 확인 불가

결과에는 `changes-unknown` **주장**이 이미 있었다 — 증거 쌍이 판정하지 못했다는 사실. `15` 는
그 위에 **점선 패널**과 **세 가지 길**을 요구하고, 그게 없었다. 취소가 확인 못한 나머지를
남긴 사용자는 **그 사실을 듣고 아무것도 할 수 없었다.**

점선이고 **중립**이다 — `12` §16: 모르는 것은 실패가 아니고, `16` §2.1 의 빨강은 실패 하나다.
`18` 이 세 문구를 다 가지고 있었다(`work.remainRead` · `work.terminal` · `work.remainNew`).
`정리 요청` 은 **요청 칸을 지나가고 보내지지 않는다** — `12` 는 보내는 것을 파일 변경 동의로
보고, D-115 는 수정도 다른 것과 똑같은 새 Work 라고 한다.

**이 상태에는 아직 그려진 증거가 없다.** e2e 의 프로젝트는 git 저장소라 증거 쌍이 언제나
답한다. 소스 수준 검사로 방아쇠·색·세 동작·보내지 않음을 확인하고, 돌연변이 둘로 확인했다
(빨강으로 칠하기 · 사용자를 대신해 보내기 — 둘 다 죽었다).

## 그리지 **않기로** 한 것 — `work.ago`

`15` SC-03 은 liveness 줄을 `마지막 관측: 파일 수정 · 12초 전` 으로 쓰고, `17` M-06 은
**상대 시각이 1초마다 째깍인다**고 한다.

상대 시각은 **계속 갱신되는 동안만 참이다.** 그걸 갱신할 수 있는 유일한 푸시는 `watchQuiet`
의 15초 tick 이라, `12초 전` 이 실제로는 27초일 때 화면에 남는다. 1초마다 다시 그리려면
**신호 없이 화면을 바꾸는 타이머**가 필요한데, 이 제품이 다른 모든 곳에서 거부하는 바로 그것이고
— 벽시계 타임스탬프가 이미 **정확하게, 그리고 낡지 않게** 말하는 사실을 사기 위해서다.

그리고 그 시간이 **결정을 좌우하는 자리에는 이미 있다**: `18` `work.nosignalTitle` —
`2분 동안 새 활동이 보이지 않아요` — 이고, 그 패널은 그것을 판정하는 tick 이 갱신한다.

PENDING 항목의 메모를 "아직 안 그림" 에서 **이 이유**로 바꿨다. 할 일이 아니라 결정이다.
