# 배치 12 QA 반영 — 제품 QA 2 BLOCKER · 8 HIGH · 8 MEDIUM · 보안 QA 1 BLOCKER · 7 HIGH

독립 QA 두 건(제품 · 기술/보안)을 배치 10~12 에 돌렸다. 440 tests · e2e 3종.

## 먼저: 핵심 안전 주장은 버텼다

보안 리뷰가 `19` §C4 의 **"자유 문장에서 셸로 가는 코드 경로가 없다"** 를 적대적으로 검증했고,
깨지 못했다. 리뷰가 실제로 한 것:

- `phrase` 를 끝까지 추적 — `match()` · 응답 객체 · **바인딩된 SQLite 파라미터** 세 곳뿐이고
  `qcRun.start` 에는 도달하지 않는다.
- **argv 공간이 유한하다는 것을 세었다: 13개.** `{npm,pnpm,yarn,bun} × run × {dev,start,serve,
  build,test}` + 고정 git 벡터.
- 적대적 입력 — ZWSP · ZWJ · word-joiner · LRM · RLO · NEL · NUL · 호환 자모 · 키릴 동형이의어 ·
  NFC/NFD · 부정문 · 복문 — **전부 잔여물이 남아 미인식**. residue 0 에 도달하는 위험 입력을
  찾지 못했다.

그리고 검사 하나가 참으로 확인됐다: **배너는 지울 수 있는 상태가 없다.** 모든 카드 상태에서
분기보다 먼저 무조건 그려지고, 그것을 숨길 CSS 규칙도 없다.

## BLOCKER

### 확인한 프로젝트와 실행되는 프로젝트가 다를 수 있었다 (보안 B1)

서랍은 `#root` 밖에 산다(설계대로 — 화면이 다시 그려져도 남아야 하니까). 그래서 **프로젝트를
바꿔도 카드가 그대로 남았다.** A 프로젝트에서 `빌드 해줘` → 카드가 `pnpm run build` 와 A 의
스크립트 본문을 보여줌 → 다른 프로젝트 열기 → B 를 열면 서랍은 그대로 → `실행` 은 클릭 시점의
`state.project.id` 를 읽는다 → **B 의 빌드 스크립트가 돈다.**

D-131 의 안전 장치 전체가 "항상 설명 후 확인" 인데, 사용자가 읽은 설명은 다시 검증되지 않았다.
프로젝트가 바뀌면 서랍 상태를 비운다(그리고 서랍을 닫는다 — cwd 없는 서랍의 모든 컨트롤은
null 프로젝트에서 실패한다).

### 여섯 규칙 중 둘이 막다른 길이었고, 제품이 거짓을 말했다 (제품 B1)

`qc.terminal.open` 과 `qc.dev.stop` 은 `available: true` 인데 **argv 가 없다**. 실행 핸들러가
`not-executable` 로 거부했고, 카드의 이유 조회는 **밑줄** 키(`no_script`…)로 되어 있는데 핸들러는
**하이픈**(`already-running`…)을 돌려주므로 `unknown_rule` 로 흘러갔다.

결과: `터미널 열어줘` → 카드가 "터미널을 열어 달라는 요청으로 이해했어요" 라고 설명 → `실행` →
**"정해진 Quick Command 가 아니에요."** 방금 여섯 중 하나로 설명한 명령에 대해서.

`19` §C4 는 명령의 출처를 셋으로 적어 두었다 — package.json 스크립트, **서랍 열기**,
**SIGTERM→5초→SIGKILL**. 뒤의 둘은 스폰하지 않는 고정 동작이다. 그 둘을 핸들러가 처리한다.
기존 테스트는 `available === true` 만 보고 **`실행` 을 누른 적이 없었다** — 이 런에서 반복해
나온 그 모양이다.

### SC-02 가 터미널이 없다고 말하고 있었다 (제품 B2)

D-134 카드가 `터미널은 아직 없어요` 로 끝났다 — 배치 12 이후 거짓이고, 같은 화면 상단 바에
`터미널` 버튼이 있다. 이제 `15` 대로 `터미널 열기` 가 **서랍을 열고 사용자의 문장을 Quick
Command 칸에 그대로 담는다.**

## MEDIUM

- **필러 목록이 13개였다. Canon 은 6개다.** 추가된 일곱(얼른·일단·우선·잠깐·혹시·부탁·좀만)이
  각각 **스폰 경로를 넓혔다** — `서버 얼른 켜줘` 가 실행됐고, Canon 목록에서는 미인식→Work 다.
  다른 목록은 Canon 이 생략해서 복원한 것이지만, 필러는 여섯을 다 적어 두었다. 되돌렸다.
- **한 프로젝트에서 하나만 돌 수 있었다.** REC-010 은 긴 QC 가 자기 프로세스에서 도는 이유를
  "서랍이 계속 쓸 수 있도록" 이라고 적어 두었다. 이제 **같은 규칙**만 거절한다.
- `handle.done.then` 에 `.catch` 가 없었다(종료가 마지막 exit 과 경합하면 주 프로세스에서
  unhandled rejection).
- 미인식·모호함 카드에 행위자 배지가 없었다.

## LOW

- **SIGTERM 이 무방비였다.** SIGKILL 만 "이미 죽었나" 를 확인했다. `07` §8.5 의 pid 재사용
  창(250 ms)이 열려 있었다. 둘 다 확인한다.
- 스크립트 본문이 줄바꿈을 잃고 흘렀다 — 판단해야 할 대상의 모양이 파일과 달랐다.
- 성공 카드의 `다시 실행` 이 복구 초록이었다(`16` 은 복구 행동에만 허용).

## 거짓 주석 넷

`run.js` 의 "env 값은 절대 출력되지 않는다"(가림은 그걸 보장하지 않는다) · "나머지는 로그로
간다"(**로그가 없다** — `output_ref` 를 쓰는 코드가 없다) · `OUTPUT_LIMIT` 을 `output_ref` 라고
라벨한 것(`output_head` 다) · pid 재사용 주석이 SIGKILL 만 덮는데 함수 전체를 덮는 것처럼
읽힌 것. `td01.js` 의 "왕복 두 번이면 구조적으로 안전" 도 B1 이 반증했다 — 두 왕복이 서로 다른
프로젝트를 가리킬 수 있었다.

## 뮤테이션

수정분 7개에 뮤턴트 7개, **7/7 killed**. 두 번 살아남았다 죽었다:

- **가운데 잘림 가드**가 중복이었다(자를 때 `bytes` 를 상한으로 올리므로 이후 청크는 자동으로
  아무것도 붙이지 않는다). 중복 분기를 지우고, **잘린 뒤 붙이는** 진짜 뮤턴트로 다시 쟀다.
- **SIGTERM 가드**를 `doesNotThrow` 로는 볼 수 없었다 — 죽은 그룹에 보내면 ESRCH 가 나고 코드가
  잡는다. `process.kill` 을 기록해 **신호가 아예 안 나갔다**를 직접 관측하도록 바꿨다.
