# 배치 24 — "파일이 자기가 하지 않는 일을 서술한 것" 에 속는 검사를 구조로 막았다

503 tests · e2e 3종. Canon 발견 없음.

이 런에서 **네 번** 같은 함정에 빠졌다. 네 번째에 규칙으로 적는 대신 구조로 만들었다.

## 네 번

| 어디 | 무엇이 일어났나 |
|---|---|
| `presence.js` | 주석이 *"`setInterval` 은 어디에도 없다"* 라고 적었고, `setInterval` 이 없는지 보는 검사가 **있다고 신고했다** |
| `nextaction.js` | 파일이 "선언된 Step" 이 무엇인지 **설명한다** — 그것을 멀리하는 게 파일의 존재 이유니까. `declared` 를 찾는 검사가 그 설명을 찾았다 |
| `main.js` | `userData` 이전 위의 주석이 `app.getPath('userData')` 를 적었고, **이전이 먼저인지** 보는 순서 검사가 주석을 먼저 찾았다 |
| `history.more` | 반대 방향. 다른 파일의 산문에 `more` 라는 단어가 있어서 **쓰이는 것처럼 보였고**, 죽은 문구 키가 그것을 찾으려고 쓴 검사를 통과했다 |

**자기가 하지 않는 일을 설명하는 파일은 좋은 코드다.** 설명과 행위를 구별하지 못하는 검사가
망가진 검사다.

## `tests/src.js` — 두 함수, 한 곳

- `code(rel)` — 주석을 벗긴 소스. **소스가 무엇을 하는지에 대한 모든 주장**이 이걸 쓴다
- `text(rel)` — 있는 그대로. **주석이 주제일 때만** 쓴다

두 번째가 진짜로 필요하다는 걸 이관 도중에 스위트가 증명했다. 두 검사가 `code` 로 바꾸자마자
깨졌는데, 둘 다 **파일이 무엇을 말하는지**가 주제였다:

- `run.js` 가 가림이 **측정되지 않았다**고 인정하는지 (`19` §C4 · q02 §5.6)
- 그리고 반대 방향의 주장 — 가림이 비밀을 막아 준다고 적은 주석 — 이 없는지

둘 다 주석이다. 벗기면 검사가 자기 주제를 볼 수 없다. `text` 로 바꾸고 **왜** 인지 그 자리에
적었다.

## 정규식이 아니라 렉서다

주석 벗기기를 정규식으로 하면 새 거짓 통과를 만든다:

- 문자열 리터럴 안의 `'http://x//y'` 가 잘린다
- 정규식 리터럴 안의 `/a\/\/b/` 가 잘린다
- 템플릿 리터럴 안의 `` `a /* not a comment */ b` `` 가 잘린다

그래서 문자열 · 템플릿 · 정규식 리터럴을 알아보는 작은 렉서다. 정규식 리터럴과 나눗셈은
**직전 유효 문자**로 가른다 — 값 뒤의 `/` 는 나눗셈이고, 연산자나 `(`·`,`·`=` 뒤면 정규식이다.

## 구조로 만든다

`tests/unit.test.js` 가 **어떤 테스트 파일도 `app/` 아래를 직접 텍스트로 읽지 못하게** 한다.
바이트 비교는 예외다 — Canon 의 `schema.sql` 과의 무결성 비교는 소스 훑기가 아니고 디코드해서도
안 된다.

그리고 **헬퍼가 진짜인지도 검사한다**: `text()` 에는 `setInterval` 이 있고 `code()` 에는 없어야
한다. 벗기지 않는 `code()` 는 위의 모든 줄을 만족시키면서 아무것도 바꾸지 않는다.

## 이관하다가 나온 것 하나

`presence.test.js` 의 **얼굴 없음** 검사가 `SRC.includes('fibonacci')` 로 "점 분포가 고른 것인지"
를 확인하고 있었다. `fibonacci` 는 **주석에만** 있다. 검사가 분포가 아니라 **분포에 대한 설명**을
읽고 있었다.

코드로 바꿨다 — 황금각 상수 `Math.PI * (3 - Math.sqrt(5))` 가 분포다.
