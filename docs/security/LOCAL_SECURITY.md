## 1. 왜 특별히 중요한가

JuQode 는 **사용자의 실제 프로젝트에서 실제 코딩 에이전트를 실행한다.**
사용자는 **비개발자**이며, 무엇이 위험한지 판단할 수 없다는 것이 제품의 전제다.

> **복잡함은 JuQode 의 것이다.** 보안 판단을 사용자에게 떠넘기는 것은 원칙 위반이다.

---

## 2. 실측 — 부모 프로세스 위생은 보안 경계가 아니다

일회용 악성 가짜 자식 프로세스를 `cwd` 고정 + `env -i` 로 띄웠다.

| 시도 | 결과 |
|---|---|
| **`../outside/` 상대경로 쓰기** | **✘ 성공했다** |
| **심링크로 루트 탈출** | **✘ 성공했다** |
| 비밀 **환경변수** 읽기 | **✔ 비어 있었다 — 이것만 통했다** |
| **무시된 `.env` 읽기 · 조용한 수정** | **✘ 성공했다** |
| **사용자 git ref 생성 · `.git/index` 삭제** | **✘ 성공했다** |
| **`cd /`** | **✘ 성공했다. `cwd` 는 경계가 아니다** |

> **신뢰 런타임의 경로 검사는 신뢰 런타임을 '지나가는' 작업만 보호한다.**
> 에이전트가 셸을 쥐고 있으면 그 검사는 우회된다.

## 3. 강제는 어디서 이루어지는가

| 층 | 실제로 강제되는가 | v0.1 |
|---|---|---|
| **① Provider 권한 강제** (Claude Code) | **된다** | **필수** |
| **② Claude Code 내장 OS 샌드박스** | **된다** | **필수** |
| **③ JuQode Git 안전장치** | 되돌림을 보장한다 | **필수** |
| ④ 부모 프로세스 위생 (`cwd` · `env`) | **거의 안 된다** | 유지하되 **보안 경계라고 부르지 않는다** |

> **v0.1 Qode 실행에는 ① + ② + ③ 이 전부 필요하다.**

```
샌드박스 사용 가능   → Qode 실행
샌드박스 사용 불가   → Qode 실행 불가. 사람 말로 이유를 말한다
```

> ## **조용한 하향 대체(silent unsandboxed fallback)를 금지한다.**
> 안전장치가 없는데 있는 척하는 것이 이 제품에서 가장 나쁜 실패다.
>
> **JuQode 는 자체 샌드박스 엔진을 v0.1 에서 만들지 않는다.**

## 4. Agent Capability Contract — 기본은 거부다

> ## **DEFAULT DENY.**

| 추가 승인 없이 허용 |
|---|
| 프로젝트 루트 **읽기** |
| 프로젝트 루트 **편집/쓰기** (스냅샷이 되돌릴 수 있게 만든다) |
| **발견된 검증 명령** (테스트 · 빌드 · 실행) |
| JuQode 가 필요로 하는 **읽기 전용 Git 명령** |

| 거부 또는 중개 |
|---|
| **임의 Bash** · **임의 네트워크 도구** |
| **루트 밖 파일 쓰기** · **Git 이력 변경** |
| **패키지 설치** · **배포 / 게시** · **자격증명 접근** |
| **무시된 파일 쓰기 — DENY** |

**Provider 보안 계약**

```
sandbox.enabled            = true
sandbox.failIfUnavailable  = true      ← 없으면 실행하지 않는다
allowUnsandboxedCommands   = false     ← 하향 대체 금지
```

```
--tools <목록>              내장 도구 중 쓸 것만. 기본 거부의 출발점
--allowedTools              패턴 허용목록
--disallowedTools           명시적 거부
--add-dir                   파일 도구를 작업 디렉터리로 한정
--permission-prompts none   프롬프트가 뜰 일은 전부 자동 거부 = DEFAULT DENY
--permission-prompt-tool    JuQode 신뢰 런타임이 승인 판정자가 된다
```

> ## ⛔ `bypassPermissions` / `--dangerously-skip-permissions` 를 쓰지 않는다

> **검증 범위:** 권한 플래그는 설치된 CLI `--help` 에서 확인했다.
> **샌드박스 설정 키의 실제 동작은 검증하지 않았다** — 유료 에이전트를 호출하지 않았다.
> **R1 에서 `probe()` 가 이것을 확인하는 자리다. 그것이 R1 Gate 다.**

## 5. 위협 모델 — 표기를 정직하게

| 표기 | 뜻 |
|---|---|
| **ENFORCED** | 실행 전에 실제로 막힌다 |
| **APPROVAL-REQUIRED** | 사람이 승인해야 진행된다 |
| **MITIGATED** | 줄이지만 못 막는다 |
| **UNSUPPORTED** | v0.1 이 다루지 않는다. **막는다고 주장하지 않는다** |

| # | 위협 | v0.1 판정 |
|---|---|---|
| 1 | 임의의 프로젝트 파일 (심링크 · 거대) | **ENFORCED** — 스캔은 읽기 전용 · 심링크를 따라가지 않는다 |
| 2 | 악의적 저장소 내용 | **ENFORCED** — 여는 것만으로 아무것도 실행하지 않는다 |
| 3 | 저장소로부터의 프롬프트 인젝션 | **MITIGATED — 완전히 못 막는다** |
| 4 | 에이전트 프로세스 실행 | **ENFORCED** (권한 + 샌드박스) |
| 5 | 임의 셸 명령 | **ENFORCED** (권한 + 샌드박스) |
| 6 | 자격증명 | **ENFORCED** — DB 에 넣지 않는다 · env 를 물려주지 않는다 |
| 7 | 심링크 · 경로 탈출 | **ENFORCED** (샌드박스 필수) |
| 8 | 루트 밖 파일 쓰기 | **ENFORCED** (샌드박스 필수) |
| 9 | 파괴적 Git 작업 | **ENFORCED** — JuQode 는 `refs/juqode/*` 만 쓴다 |
| 10 | 외부 네트워크 송신 | **APPROVAL-REQUIRED** |
| 11 | 로그에 비밀이 섞인다 | **MITIGATED** — 마스킹하되 원본은 삭제하지 않는다 |
| 12 | **무시된 비밀 파일(`.env`) 수정** | **DENY** — 되돌릴 수 없다 |
| 13 | 실행 중 외부 편집 오귀속 | **MITIGATED** — 소유권 `UNKNOWN` |

## 6. 정직하게 못 막는다고 말하는 것

| | 왜 |
|---|---|
| **프롬프트 인젝션을 완전히 막지 못한다** | 저장소 내용은 반드시 모델에 들어가야 한다 |
| **에이전트가 프로젝트 안에서 하는 나쁜 변경** | 막지 않는다. **되돌릴 수 있게** 만든다 |
| **이미 커밋된 비밀** | JuQode 가 만든 문제가 아니다. **발견하면 말한다** |
| **부모 프로세스만으로 자식을 가두는 것** | **실측으로 불가능이 확인되었다** |
| **샌드박스 없는 환경에서의 Qode** | **실행하지 않는다.** 조용히 약해지지 않는다 |
| **무시된 파일의 되돌리기** | 스냅샷 밖이다. 그래서 **쓰기 자체를 거부한다** |

## 7. 미결

- **Claude Code 샌드박스 · 권한의 실제 강제력** → **R1 Gate** (`probe()`)
- **`chrome-sandbox` SUID 패키징** → **D1**
- 비밀 패턴 마스킹의 정확도 · 마스킹본과 원본의 접근 분리
- 샌드박스 사용 불가 시의 **사람 말 문구** (Git 어휘 금지 · 다음 행동 제시)
