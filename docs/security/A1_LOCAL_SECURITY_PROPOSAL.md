## 1. 왜 JuQode 에서 이것이 특별히 중요한가

JuQode 는 **사용자의 실제 프로젝트에서 실제 코딩 에이전트를 실행한다.**
사용자는 **비개발자**이며, 무엇이 위험한지 판단할 수 없다는 것이 제품의 전제다.

> **원칙 1 — 복잡함은 JuQode 의 것이다.**
> 보안 판단을 사용자에게 떠넘기는 것은 이 원칙의 정면 위반이다.

---

## 2. 실측 — 부모 프로세스 위생은 보안 경계가 아니다

일회용 악성 가짜 자식 프로세스를 **A1a 가 안전하다고 한 구성**(`cwd` 고정 + `env -i`)으로 띄웠다.
**진짜 유료 코딩 에이전트를 부르지 않았다.**

| 시도 | A1a 의 주장 | **실측 결과** |
|---|---|---|
| 프로젝트 루트 안 쓰기 | 허용 | ✔ 성공 (정상 동작) |
| **`../outside/` 상대경로 쓰기** | **막힌다** | **✘ 성공했다** |
| **심링크로 루트 탈출** | **막힌다** | **✘ 성공했다** |
| 비밀 **환경변수** 읽기 | 막힌다 | **✔ 비어 있었다 — 이것만 통했다** |
| **무시된 `.env` 읽기 · 조용한 수정** | 언급 없음 | **✘ 성공했다. 스냅샷 밖이라 되돌릴 수도 없다** |
| **사용자 git ref 생성** | 막힌다 | **✘ 성공했다** |
| **`.git/index` 삭제** | 막힌다 | **✘ 성공했다** |
| **`cd /`** | — | **✘ 성공했다. `cwd` 는 경계가 아니다** |
| 같은 것을 `bubblewrap` 안에서 | — | **✔ 루트 밖 쓰기가 차단되었다** |

> **신뢰 런타임의 경로 검사는 신뢰 런타임을 '지나가는' 작업만 보호한다.**
> 에이전트가 셸을 쥐고 있으면 그 검사는 우회된다.

## 3. 강제는 어디서 이루어지는가 — A1b.1 에서 확정되었다

**A1b 는 OS 샌드박스를 "선택"으로 두었다. PM 이 그것을 필수로 올렸다.**
현재 Claude Code 는 **내장 Bash 샌드박스**를 제공하므로, JuQode 가 샌드박스를 직접 만들 필요가 없다.

| 층 | 실제로 강제되는가 | **v0.1** |
|---|---|---|
| **① Provider 권한 제어** (Claude Code) | **된다** | **필수** |
| **② Claude Code 내장 OS 샌드박스** | **된다** | **필수** — A1b 의 "선택" 을 뒤집었다 |
| **③ JuQode Git 안전장치** | 되돌림을 보장한다 | **필수** |
| **④ 부모 프로세스 위생** (`cwd` · `env`) | **거의 안 된다** — env 누출 차단만 | 유지하되 **보안 경계라고 부르지 않는다** |

> **v0.1 실행 보안 계약 = ① + ② + ③.** 셋 중 하나라도 없으면 Qode 를 실행하지 않는다.

### 샌드박스를 못 쓰면 Qode 를 실행하지 않는다

```
Linux v0.1
  샌드박스 사용 가능   → Qode 실행
  샌드박스 사용 불가   → Qode 실행 불가. 사람 말로 이유를 말한다
                        조용히 샌드박스 없이 실행하지 않는다
```

> **조용한 하향 대체(silent unsandboxed fallback)를 금지한다.**
> 안전장치가 없는데 있는 척하는 것이 이 제품에서 가장 나쁜 실패다 (P3).

### JuQode 는 자체 샌드박스 엔진을 만들지 않는다

v0.1 에서 JuQode 소유의 샌드박스를 구현하지 않는다.
**Provider 가 제공하는 것을 요구하고 검증할 뿐이다.** (`probe()` 가 그 자리다 — A1-10)

## 4. v0.1 AGENT CAPABILITY CONTRACT — 기본은 거부다

> **DEFAULT DENY.** 명시적으로 허용한 것만 된다.

| 추가 승인 없이 허용 | 왜 |
|---|---|
| 프로젝트 루트 **읽기** | 이해와 수정의 전제 |
| 프로젝트 루트 **편집/쓰기** | Qode 의 본체. **스냅샷이 되돌릴 수 있게 만든다** |
| **발견된 검증 명령** (테스트·빌드·실행) | Evidence 의 원천. 프로젝트에서 발견한 것만 |
| JuQode 가 필요로 하는 **읽기 전용 Git 명령** | 상태 파악 |

| 거부 또는 중개 | 왜 |
|---|---|
| **임의 Bash** | 위 계약 전체를 무력화한다 |
| **임의 네트워크 도구** | 송신 경계를 알 수 없다 |
| **루트 밖 파일 쓰기** | 사용자의 기계다 |
| **Git 이력 변경** | 사용자의 이력이다 |
| **패키지 설치** | 무엇이 들어오는지 먼저 보여준다 |
| **배포 / 게시** | `destructive` |
| **자격증명 접근** | D-058 |
| **무시된 파일(`.env` 등) 쓰기** | **되돌릴 수 없다** — 스냅샷 밖이다 |

### Provider 보안 계약 (PROPOSED · PM 방향)

**샌드박스**
```
sandbox.enabled              = true
sandbox.failIfUnavailable    = true      ← 없으면 실행하지 않는다
allowUnsandboxedCommands     = false     ← 하향 대체 금지
```

**권한 — 기본 거부**
```
--tools <목록>              내장 도구 중 쓸 것만 지정. 기본 거부의 출발점
--allowedTools              "Bash(git status:*)" 형태의 패턴 허용목록
--disallowedTools           명시적 거부
--add-dir                   파일 도구를 작업 디렉터리로 한정한다
--permission-prompts none   프롬프트가 뜰 일은 전부 자동 거부 = DEFAULT DENY
--permission-prompt-tool    JuQode 신뢰 런타임이 승인 판정자가 된다
```

> ## ⛔ `bypassPermissions` / `--dangerously-skip-permissions` 를 쓰지 않는다
> 그것을 쓰는 순간 위 계약 전체가 장식이 된다.

> **검증 범위 (정직하게):** 위 **권한 플래그들은 설치된 CLI 의 `--help` 에서 실제로 확인했다.**
> **샌드박스 설정 키는 PM 이 제시한 방향이며 이 저장소에서 검증하지 않았다** —
> 유료 에이전트를 호출하지 않았기 때문이다. **R1 에서 `probe()` 로 실제 확인해야 한다.**

## 6. 경계 — 어느 런타임을 고르든 같다

```
UI 프로세스        Canvas + DOM 뿐. Node 없음 · fs 없음 · 프로세스 실행 없음
      │            타입된 IPC — 동사 목록이 고정된다
신뢰 로컬 런타임     경로 정규화 · 루트 잠금 · Git · DB · 자격증명 · 에이전트 수명주기
      │
에이전트 프로세스    cwd 고정 · env 상속 없음 · stdout 은 데이터로만 · 취소 가능
```

> **이 그림은 위생(hygiene)이지 보안 경계가 아니다.** 경계는 §3 의 ① 과 ② 가 만든다.
>
> **stdout 을 절대 명령으로 해석하지 않는다.**
> 에이전트의 출력이 JuQode 의 행동을 직접 지시할 수 있으면 위협 3이 곧바로 위협 4가 된다.

## 7. 정직하게 못 막는다고 말하는 것

| | 왜 |
|---|---|
| **프롬프트 인젝션을 완전히 막지 못한다** | 저장소 내용은 반드시 모델에 들어가야 한다. 완화만 가능하다 |
| **에이전트가 프로젝트 안에서 하는 나쁜 변경** | 막지 않는다. **되돌릴 수 있게** 만든다 — 그것이 A1-15 의 존재 이유다 |
| **비밀이 이미 저장소 안에 커밋되어 있는 경우** | JuQode 가 만든 문제가 아니고 고칠 수도 없다. **발견하면 말한다** |
| **OS 자격증명 저장소가 없는 환경** | 실측 — 있다고 전제할 수 없다. **평문으로 떨어지지 않고, 약해졌다는 사실을 말한다** |
| **부모 프로세스만으로 자식을 가두는 것** | **실측으로 불가능이 확인되었다.** 그래서 v0.1 은 **Provider 샌드박스를 필수로 요구한다** |
| **샌드박스가 없는 환경에서의 Qode** | **실행하지 않는다.** 조용히 약해지지 않는다 |
| **무시된 파일의 되돌리기** | 스냅샷 밖이다. 그래서 **쓰기 자체를 승인 대상으로 올린다** |

> **조용히 약해지지 않는다.** 이것이 P3(HONESTY)의 보안판이다.

## 8. 승인 경계 — 모달을 남발하지 않는다

| 효과 | 등급 | v0.1 |
|---|---|---|
| 프로젝트 루트 **안**의 파일 쓰기/삭제 | **reversible** | 승인 없음 — 스냅샷이 되돌릴 수 있게 만든다 |
| **무시된 파일(`.env` 등) 쓰기** | **irreversible** | **승인 필요.** 스냅샷 밖이라 되돌릴 수 없다 |
| 루트 **밖** 쓰기 · 심링크 탈출 | **destructive** | 차단 |
| 네트워크 송신 (Agent 호출 제외) | **irreversible** | 대상을 먼저 보여준다 |
| 패키지 설치 | **irreversible** | 무엇이 들어오는지 보여준다 |
| 과금 · 배포 · 게시 · 권한 변경 | **destructive** | + 사전 증거 + 의도의 재진술 |
| Git 이력 파괴 | **destructive** | v0.1 에서 하지 않는다 |

> **Qode 직전 스냅샷이 프로젝트 안의 모든 변경을 `reversible` 로 강등시킨다.**
> 그래서 승인이 필요한 표면은 **경계를 넘는 행동만** 남는다 —
> 이것이 *"확인 모달 남발은 실패다"* 를 구조적으로 달성하는 방법이다.

## 9. 미결

- **Claude Code 샌드박스·권한의 실제 강제력을 검증하지 않았다** — 유료 에이전트를 부르지 않았다.
  **R1 에서 `probe()` 가 이것을 확인하는 자리다**
- **샌드박스 사용 불가 시의 사람 말 문구**는 아직 쓰지 않았다 (Git 어휘 금지 · 다음 행동 제시)
- 비밀 패턴 마스킹의 정확도 · 마스킹본과 원본의 접근 분리 방식
- 프롬프트 인젝션 완화의 실제 효과는 **측정하지 않았다**
- OS 자격증명 저장소가 없을 때의 대체 경로 최종 형태 → A1-14 와 함께 결정
