# 작업 현황과 작업 목록

2026-10-22 · V1-305 / V1-311의 화면 개선 후보. 공식 WBS 완료 판정이나 배포 승인이 아니다.

## 사용 흐름

프로젝트를 열면 작업 현황에서 **시작 전 / 진행 중 / 확인 필요 / 검토 / 완료**의 개수와 완료 수·전체 수를 본다. 상태를 누르면 보드와 목록이 해당 상태로 좁혀진다. 같은 상태를 한 번 더 누르거나 왼쪽 **전체**를 누르면 전체 작업으로 돌아온다. 필터를 바꿔도 상단 집계는 프로젝트 전체를 유지한다.

위쪽 **목록**을 누르면 **작업 목적 / 상태 / 최근 실행 / 다음 확인**을 표로 본다. 작업명을 누르면 기존 작업 상세가 열린다. Tab으로 작업명에 이동한 뒤 Enter로 열 수 있다. 기존 보드 선택·Inspector·시도/근거 링크·완료 조건 검토 경로를 그대로 사용한다. 별도 실행, 승인, 자동 완료 기능은 추가하지 않는다.

## 집계의 의미

- 데이터는 기존 `taskList(projectId)`와 각 `taskDetail(taskId)`에서 읽는다. 분류는 기존 `columnFor(task, latestRun)`를 재사용한다.
- **완료 수 / 전체 수는 저장된 Task 기준**이다. PM의 JuQode 개발 WBS `17/96`을 사용자 프로젝트의 진행률로 넣지 않는다.
- 성공한 Run만으로 Task를 완료 처리하지 않는다. 완료 조건이 확인되지 않은 성공 Run은 검토에 남는다. `ended_unknown`은 완료된 Task에 속해도 확인 필요로 남는다.
- 저장 Task와 연결되지 않은 Run은 기존 별도 표시를 유지하고 상단 합계와 표의 Task 행에 넣지 않는다. 보드의 기존 칸별 개수에는 해당 Run이 포함될 수 있으며, 카드에는 연결되지 않은 시도라는 설명이 남는다.
- 표의 최근 실행에는 실제 최신 Run의 결과와 기록 시각을 표시한다. Run이 없으면 실행 기록이 없음을 표시한다. 역할·검수자·승인자를 새로 추정하지 않는다.
- 최초 읽기에는 집계를 숨기고 읽는 중이라고 알린다. 재읽기 중 기존 집계는 직전에 읽은 기록이라고 알린다. 목록 또는 Task 상세를 읽지 못하면 상태를 시작 전으로 추측하지 않고 집계·목록 대신 오류와 다시 읽기를 표시한다.
- 실제 전체 작업 0개와 필터 결과 0개를 구분한다. 프로젝트에 작업이 있을 때는 첫 작업을 만들라는 안내를 표시하지 않는다.

## 구현과 검증 범위

현재 구현은 `app/renderer/screens/sc02.js`, 같은 경로의 `sc02.css`, `app/renderer/copy.js`에 있다. 새 문구는 `C.gap.board`에 두었다. 데이터 모델·저장·권한·Provider·실행 계약·Canon을 바꾸지 않는다. 표는 기존 테마 토큰을 사용하며 600px보다 좁은 작업 영역 안에서 가로 스크롤한다.

Worker 검증은 `tests/board-overview.test.js`, `board-column.test.js`, `task.test.js`, `theme.test.js`, `unit.test.js`와 `reader.test.js`에 한정한다. 전체 Unit/E2E를 반복하지 않는다. 아래 실제 화면 항목은 독립 QA가 최종 정확한 SHA에서 확인해야 한다.

1. 합성 로컬 Task를 기존 저장 경로에 넣고 상태별 합계, 성공 Run→검토, unknown→확인 필요, 연결되지 않은 Run 제외를 확인한다.
2. 상태 요약 ↔ 왼쪽 전체/확인 필요/완료 필터, 보드 ↔ 목록, 실제 전체 0개 ↔ 필터 0개를 확인한다.
3. 실제 Tab/Enter로 요약·목록·작업명을 조작하고, 포커스 표시와 재렌더 후 포커스 보존, 기존 Inspector와 닫기 동작을 확인한다.
4. 1024px 이상 좁은 창과 넓은 창, light/dark에서 표·요약·Inspector가 겹치거나 정보를 잘라내지 않는지 확인한다.
5. 초기 읽기·재읽기·거부된 Task 상세 읽기에서 거짓 완료/시작 전/0개가 나타나지 않는지 확인한다.
