## 1. 풀어야 하는 긴장

Canon 은 자리(Semantic Place)를 이렇게 못박았다.

> **테두리가 없다 · 셀 수 없다 · 떼어낼 수 없다 · 개체가 아니다. 재료의 성질이다.**

그러나 저장은 반대를 요구한다.

- Problem 은 자리에 매여야 한다 (MUST #6)
- 이름 정정은 **재스캔에도 살아남아야** 한다
- Evidence 와 Deep View 가 자리를 참조한다

**저장하려면 안정된 동일성이 필요하다.** 이것이 A1 이 풀어야 하는 구조적 긴장이다.

## 2. 제안 — 안이 아니라 밖에서 개체가 아니다

| | |
|---|---|
| **내부** | `place_id` 는 **안정된 내부 식별자**다. 한 번 생기면 바뀌지 않는다 |
| **사용자** | 자리를 만들 수도 지울 수도 옮길 수도 없다. **목록으로 열거되지 않는다.** 이름은 집혔을 때만 온다 |
| **재스캔** | **매핑 지문으로 재식별**한다. 확신이 높으면 같은 자리에 새 revision 을 붙인다 → 정정 · Problem · Evidence 가 살아남는다 |
| **겹침** | 자리 ↔ 소스는 **N:N**. 한 파일이 두 자리에 속할 수 있다. **분할이 아니다** |

> **이것을 정하지 않으면 `Place` 테이블을 쓰는 순간 조용히 Feature Map 으로 되돌아간다.**

### ⚠ A1b 정정 — 동일성을 매핑 지문에서 끌어내지 않는다

A1a 는 `place_id` 를 매핑 서명에서 **파생**시켰다.
**그러면 파일 하나만 옮겨도 자리가 다른 자리가 되고, 사용자의 이름 정정이 통째로 증발한다.**

```
SemanticPlace           안정된 내부 id · current_revision → · confidence
SemanticPlaceRevision   place_id · mapping_fingerprint · source_mappings · model_version
PlaceNaming             place_id · name · origin        ← 지문이 아니라 '자리'에 묶인다
```

| | |
|---|---|
| **매핑 지문의 역할** | **재식별 신호(re-identification signal)** 다. 영구 동일성이 아니다 |
| 확신이 높으면 | 같은 `place_id` 에 새 revision → **정정이 살아남는다** |
| 확신이 낮으면 | 새 자리로 본다. **옛 자리를 지우지 않는다** — 사람이 이을 수 있다 |
| 목표 | **평범한 리팩터(파일 이동 · 이름 변경 · 분할)를 정정이 견뎌야 한다** |

### ⚠ A1b 정정 — 5~7 은 렌더링 예산이지 아는 자리의 상한이 아니다

A1a 는 *"자리 7개를 넘기지 않는다"* 를 **모델 규칙**으로 적었다. **범주 오류다.**

| | |
|---|---|
| **틀린 읽기** | 자리는 최대 7개다. 8번째부터는 `UNKNOWN` 이다 |
| **옳은 읽기** | **5~7은 한 화면에서 방향으로 또렷이 구분되는 수 — 렌더링 / 관측 예산이다** |
| **핵심** | **아는데 지금 안 보이는 것 ≠ 모르는 것** |

Semantic Model 은 **아는 만큼 전부 담는다.** 20개면 20개다.
한 번에 몇 개를 또렷이 보여주는가는 **L5 OBSERVATION / Semantic Zoom** 의 문제다.

> `confidence`(뜻을 아는가)와 `visibility`(지금 그리는가)는 **서로 다른 축이다.**
> 예산 밖을 `UNKNOWN` 으로 적으면 **아는 것을 모른다고 거짓말하는 것**이며 P3 위반이다.

## 3. 자리는 어떻게 나오는가 (PROPOSED)

```
진입점 · 라우트 후보  ──씨앗──┐
매니페스트 · 의존 그래프 ─────┼──▶ 후보 덩어리 ──▶ AI 라벨 ──▶ 사람 정정
Git 변경 동시성 ─────────────┘         │
                                      └─▶ 확신 낮음 → 『모르는 곳』  (예산 초과는 UNKNOWN 이 아니다)
```

| 규칙 | 근거 |
|---|---|
| 파일 빈도는 자리를 만들지 못한다 | 실측 — 한 저장소는 파일의 99%가 로그였다 |
| 폴더는 자리가 아니다 | 폴더는 분할이고, 자리는 겹친다 |
| **한 화면에 또렷이 그리는 자리는 5~7개** | 3R.5 수용량 한계. **모델의 상한이 아니라 렌더링 예산이다** |
| 뜻이 없는 곳은 `모르는 곳` | P3 — 발명하지 않는다 |
