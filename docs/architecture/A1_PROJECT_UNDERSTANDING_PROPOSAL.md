## 1. 문제

Local Project 를 열었을 때 **무엇을 근거로 "이 Software 를 이해했다"고 말하는가.**
이해가 없으면 그릴 몸이 없고, 몸이 없으면 주 인터페이스가 없다.

---

## 2. 제안 — 2단 + 사람 정정

```
① 결정적 로컬 스캔        오프라인 · 재현 가능 · 빠르다
        ↓  사실
② AI 의미 분석            이름 · 뜻 · 사람 말. 반드시 ①의 사실을 인용한다
        ↓  의미
③ 사람 정정               영구 저장된다. 다음에 다시 묻지 않는다
```

**①만으로도 몸은 뜬다.** ②가 실패하거나 오프라인이면 자리는 `모르는 곳` 으로 남고 **열기는 실패하지 않는다.**

---

## 3. 경계 — 무엇을 로컬이 하고 무엇을 AI 가 하는가

| **로컬만** | **AI만** |
|---|---|
| 파일·디렉터리 그래프 · 크기 | 자리의 **이름** |
| import / 의존 그래프 | 자리의 **한 줄 설명** |
| 매니페스트 · 선언된 의존성 | 덩어리 → 하나의 뜻으로 묶기 |
| 라우트 · 엔트리 후보 | Problem 의 **사람 말 한 줄** |
| 테스트/빌드 설정과 명령어 | 자리 사이의 의미적 거리 |
| Git 이력 · 변경 빈도 | Outcome 문장 |
| 실행 관측 · 종료코드 · stderr | — |

> **하드 규칙:** AI 가 말한 모든 것은 **로컬 사실을 인용해야 한다.**
> 인용을 못 붙이는 발화는 저장하지 않는다. — 번역은 아래에서 위로 (D-011)

---

## 4. 실측이 뒤집은 것

| 가정 | 실측 |
|---|---|
| *"대형 저장소는 로컬 스캔이 느리니 AI 에 맡기자"* | **30,104 파일 / 268ms.** 로컬 스캔은 병목이 아니다 |
| *"파일이 많은 곳이 중요한 곳이다"* | 한 실제 저장소는 30,104개 중 **29,767개가 `.log`** 였다 |

> **파일 수는 의미가 아니다.**
> 자리는 **진입점 · 의존 그래프 · 매니페스트**에서 나온다. 파일 수는 **질량의 하한**에만 쓴다.
> 이것은 Canon §12.2 가 말한 *"파일 목록은 구조가 아니지만 구조처럼 보인다"* 의 구현판이다.

---

## 5. 정직성 규칙

- **모르는 곳은 모르는 곳으로 남는다.** 발명하지 않는다 (P3)
- **관측하지 않은 것은 계산하지 않는다** (L5)
- **Empty Software 는 자리 0개.** 가짜 자리를 미리 만들지 않는다
- **또렷이 구분되는 자리는 5~7개.** 넘치면 자리를 더 만들지 않고 `모르는 곳` 으로 남긴다

---

## 6. 미결

- 이해가 **재현 가능한가** — 같은 저장소를 두 번 열면 같은 몸이 나오는가. 실제 저장소에서 측정하지 않았다
- 증분 갱신은 **V1** 이다. v0.1 은 매번 다시 이해한다
