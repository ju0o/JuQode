## 1. 되돌리기 = 안전감 = v0.1 의 핵심 가치

`04` §8 Anti-Goals: *"Git 은 어려우니 v0.1 에서 빼자"* 는 금지되어 있다.
되돌리기가 안전하지 않으면 v0.1 의 핵심 가치가 없다.

**Return Safety 세 조건 (D-045)**

1. 사라지는 것과 **남는 것**을 함께 예고한다
2. **되돌리기 자체가 되돌려진다**
3. 버린 상태는 **보관된다** — *"약속한 숫자와 보관한 숫자가 달라서는 안 된다"*

## 2. 다섯 방법을 실제로 비교했다

| 방법 | 미추적 파일 담김 | 사용자 상태 불변 | 이력 오염 | 판정 |
|---|---|---|---|---|
| 커밋 | ✅ | ❌ HEAD 가 움직인다 | ❌ 사용자 이력에 낀다 | **기각** |
| `stash create` | ❌ **실측 실패** | ✅ | ✅ | **기각** |
| 패치 파일 | ✅ | ✅ | ✅ | 보조로만 |
| worktree | 부분 | ✅ | ✅ | **v0.1 연기** |
| 스냅샷 객체 + 자체 ref **(트리 하나 · A1a 안)** | ✅ | **✘ 인덱스를 파괴했다** | ✅ | **기각** |

## 3. 제안 — 스냅샷 커밋 객체 + `refs/juqode/*`

```
refs/juqode/safety/<execution_id>/work    Qode 직전 워킹트리 (미추적 포함)
refs/juqode/safety/<execution_id>/index   Qode 직전 사용자 인덱스 (스테이징)
refs/juqode/discarded/<rollback_id>    되돌리기로 버려진 상태. 보관된다
refs/juqode/equilibrium/<time_id>      확인된 평형. Software Time 의 점
```

### ⚠ A1b 정정 — 스냅샷은 트리 하나가 아니라 둘이다

A1a 는 워킹트리 하나만 찍고, 복원할 때 `git read-tree HEAD` 를 했다.
**그것이 사용자의 스테이징을 파괴한다.** 실측으로 확인했다 —
부분 스테이징(`MM`)이 사라지고, 스테이징된 파일이 미스테이징으로 강등되고, 이름 변경 staging 이 풀렸다.

```
INDEX_TREE = 사용자의 인덱스 그대로        (write-tree — 인덱스를 읽기만 한다)
WORK_TREE  = 워킹트리 그대로 (미추적 포함)  (별도 GIT_INDEX_FILE 로 read-tree HEAD + add -A)
```

복원은 셋을 순서대로. **사용자 인덱스를 `HEAD` 로 리셋하지 않는다.**

```
① 스냅샷 이후 생긴 파일만 정확히 지운다     diff --diff-filter=A
② 워킹트리를 WORK_TREE 로 되돌린다          별도 인덱스 + checkout-index
③ 사용자 인덱스를 INDEX_TREE 로 되돌린다    read-tree INDEX_TREE  ← HEAD 가 아니다
```

**HEAD · 인덱스 · 워킹트리를 하나도 건드리지 않는다** — 실측 확인.

| 성질 | 어느 약속을 참으로 만드는가 |
|---|---|
| 사용자 상태 불변 · `git log` 에 안 뜬다 | 하던 일이 끊기지 않는다 |
| ref 가 GC 로부터 지킨다 | **"보관됨 · 없어지지 않았습니다"** (조건 3) |
| 되돌리기 전에 먼저 보관한다 | **되돌리기의 되돌리기** (조건 2) |
| 두 트리를 비교해 목록을 만든다 | 사라지는 것/남는 것이 **계산된 사실**이 된다 (조건 1) |
| 약속 목록 = 보관 객체의 실제 내용 | 같은 객체에서 나오므로 **구조적으로 일치한다** |

## 4. 여덟 질문에 대한 답 (전부 실측 근거 있음)

실험은 열 가지 초기 상태를 만들었다 — 정상 추적 · 더러운 추적 · 스테이징 · **부분 스테이징** ·
미추적 · **무시된 `.env`** · 삭제 · **이름 변경** · **심링크** · **중첩 저장소**.

| 질문 | 답 | 실측 |
|---|---|---|
| Qode 전에 저장소가 더럽다면 | **그대로 진행한다** | ✔ |
| 추적 안 된 파일은 | **담기고 복원된다** | ✔ |
| **HEAD** | **불변** | ✔ |
| **사용자 스테이징 (부분 스테이징 · 이름 변경 포함)** | **정확히 동일** | ✔ |
| 사용자 변경과 JuQode 변경 구분 | 시작 직전 스냅샷 **+ Agent Event 귀속** | — |
| 되돌리기 구현 | 추가분 정확 삭제 → 워킹트리 복원 → **인덱스 복원** | ✔ |
| 되돌리기의 되돌리기 | 직전 상태를 `discarded` 로 먼저 보관 | ✔ |
| **중첩 저장소 · 심링크** | **보존됨** | ✔ |
| Git 저장소가 없다면 | 프로젝트 **밖**의 그림자 저장소 | ✔ |
| **무시된 `.env` 를 에이전트가 고쳤다면** | **✘ 도둑맞은 채 남는다 — 스냅샷 밖이다** | ✔ (실패 확인) |

> **찾은 함정:** 나이브한 복원은 **거짓이다** — 스냅샷 이후 생긴 파일이 그대로 남는다.
> "그때 그대로"를 참으로 만들려면 추가된 파일을 **정확히 열거해서 지워야** 한다.

## 6. v0.1 무시 파일(ignored) 정책 — A1b 신설

> **무시된 파일은 자동 되돌리기 범위 밖이다. 그리고 에이전트는 그것을 조용히 고칠 수 없다.**

| 규칙 | 왜 |
|---|---|
| `.gitignore` 대상은 **스냅샷에 없다** | 빌드 산출물까지 담으면 스냅샷이 감당 안 된다 |
| **그러므로 되돌려도 안 돌아온다** | 실측으로 확인했다 |
| **에이전트의 무시 파일 쓰기 = `APPROVAL-REQUIRED`** | `.env` 가 정확히 여기 있다. 되돌릴 수 없는 것을 조용히 고치게 두지 않는다 |
| 그래도 고쳐야 한다면 | 사람이 승인하고 **JuQode 가 그 파일만 따로 보관한다** |
| 화면이 말한다 | *"이 파일은 되돌리기에 포함되지 않습니다"* |

### 함께 정한 경계

| | v0.1 |
|---|---|
| **프로젝트 밖을 가리키는 심링크에 쓰기** | **금지.** 단 강제 주체는 **Provider 권한 계층**이다 — 부모 프로세스가 아니다 |
| **중첩 저장소 / 서브모듈** | **자동 쓰기 대상이 아니다.** 보존하되 건드리지 않는다 |
| **실행 중 외부 동시 편집** | **JuQode 것으로 귀속하지 않는다.** 소유권 `UNKNOWN` |

## 7. 정직하게 남기는 한계

1. **무시된 파일은 되돌려도 안 돌아온다** — 위 정책으로 다룬다
2. **매우 큰 저장소의 스냅샷 시간은 여전히 측정하지 않았다.** 실험은 작은 저장소였다
3. **`git write-tree` 는 병합 충돌 상태에서 실패한다.** 그 경우의 동작은 미설계
