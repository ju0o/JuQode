## 1. 이해의 순서

```
① LOCAL FACTS          결정적 · 오프라인 · 재현 가능
        ↓
② AI SEMANTIC INFERENCE 이름 · 뜻 · 사람 말. 반드시 ①을 인용한다
        ↓
③ HUMAN CORRECTION      영구 저장된다. 다음에 다시 묻지 않는다
```

> ## **Software 를 여는 것이 AI 가용성에 의존해서는 안 된다.**
> ①만으로 **몸이 뜬다.** ②가 실패하거나 오프라인이면 자리는 `모르는 곳` 으로 남고
> **열기는 실패하지 않는다. 모르는 것은 모르는 채로 남는다.**

---

## 2. 경계 — 무엇을 로컬이 하고 무엇을 AI 가 하는가

| **로컬만** (결정적) | **AI만** (의미) |
|---|---|
| 파일·디렉터리 그래프 · 크기 | 자리의 **이름** |
| import / 의존 그래프 | 자리의 **한 줄 설명** |
| 매니페스트 · 선언된 의존성 | 덩어리 → 하나의 뜻으로 묶기 |
| 라우트 · 엔트리 후보 | Problem 의 **사람 말 한 줄** |
| 테스트/빌드 설정과 명령어 | 자리 사이의 의미적 거리 |
| Git 이력 · 변경 빈도 | Outcome 문장 |
| 실행 관측 · 종료코드 · stderr | — |

---

## 3. 출처(origin) — 셋

| `origin` | 로컬 사실 인용 | 뜻 |
|---|---|---|
| `LOCAL_FACT` | — | 결정적 분석이 관측한 사실. 그 자체가 근거다 |
| `AI_INFERENCE` | **필수** | 인용을 못 붙이면 **저장하지 않는다** |
| `USER_CORRECTION` | **불필요** | **가장 높은 우선순위.** 사용자는 근거를 대야 하는 쪽이 아니다 |

---

## 4. 정직성 규칙

- **파일 수는 의미가 아니다.** 자리는 **진입점 · 의존 그래프 · 매니페스트**에서 나온다.
  파일 수는 **질량의 하한**에만 쓴다
- **관측하지 않은 것은 계산하지 않는다**
- **Empty Software 는 자리 0개.** 가짜 자리를 미리 만들지 않는다
- **5~7 은 렌더링 / 관측 예산이다.** 아는 자리의 상한이 아니다 —
  **아는데 지금 안 보이는 것을 `모르는 곳` 으로 적지 않는다**
